## Post-Exploitation Modules: 5-F through 5-J + Tool Integrations

> **Reviewer Role:** Senior Security Architect & Engineering Lead

## Executive Summary

Phase 5 is the operational centrepiece of FORGE v7.1. The evasion-forward design philosophy is
well-executed — TLS-native shell variants, Gaussian jitter on beacon intervals, and LOLBin-aligned
persistence naming all demonstrate mature red-team thinking. This expanded review incorporates two
tool integrations flagged for Phase 5: **CyberChef** (encoding validation of exfiltrated payloads)
and **LeakLooker** (post-exfiltration paste-site monitoring). Both are detailed below with schema
additions, implementation patterns, OPSEC constraints, and testing requirements.

The CyberChef role in Phase 3 (encoding chain cross-validation) is already documented in Chunk 4.
Its role here is narrower and distinct: **verifying the integrity of encrypted exfil bundles at
the operator station** before they are marked as confirmed captures. The LeakLooker integration is
a net-new capability for Module 5-H that introduces a post-exfil monitoring loop.

## Part I — CyberChef Integration in Phase 5

### Role Distinction from Phase 3

| Context | CyberChef Role |
|---------|----------------|
| Phase 3 (Chunk 4) | Validate that `EncodingChain` output is correctly reversible; catch encoding regressions before deployment |
| **Phase 5 (this document)** | **Verify AES-256-GCM + gzip bundle integrity on the operator station after C2 retrieval; confirm that the exfil pipeline round-trips correctly** |

CyberChef is **never a runtime dependency** on the target. It is exclusively an operator-side
validation tool used during pre-engagement testing and post-collection verification.

---

### 5-H Integration Point: Exfil Bundle Verification

After `Exfiltrator` uploads chunks to the C2 channel, the operator station reassembles them into a
single `<sha256>.enc` bundle. Before the operator marks the collection as confirmed and moves to
Phase 6 reporting, FORGE should surface a CyberChef verification recipe so the operator can
confirm the bundle decrypts and decompresses correctly with an independent reference implementation.

#### Recipe Generation

```python
# forge/phase5/exfil_recipe.py
"""
Generates a CyberChef JSON recipe for offline verification of an AES-256-GCM + gzip exfil bundle.
Intended for operator-side validation ONLY. Never called from agent or target-side code.
"""
from __future__ import annotations

import json
from pathlib import Path


def build_cyberchef_recipe(
    key_hex: str,       # 64-char hex AES-256 key
    nonce_hex: str,     # 24-char hex nonce (96-bit GCM nonce)
) -> dict:
    """
    Returns a CyberChef recipe dict that:
      1. Decodes the bundle from Base64
      2. Decrypts AES-256-GCM (key + nonce from engagement DB)
      3. Decompresses gzip
    """
    return {
        "recipe": [
            {"op": "From Base64",    "args": ["A-Za-z0-9+/=", True]},
            {
                "op": "AES Decrypt",
                "args": [
                    {"option": "Hex", "string": key_hex},
                    {"option": "Hex", "string": nonce_hex},
                    "GCM", "Raw", "Raw",
                    {"option": "Hex", "string": ""},  # AAD empty
                    True,  # Return tag
                ],
            },
            {"op": "Gunzip", "args": []},
        ]
    }


def emit_recipe_file(key_hex: str, nonce_hex: str, output_path: Path) -> None:
    """
    Writes the CyberChef recipe to a local JSON file for operator use.
    The key and nonce originate from the engagement DB (age-decrypted at invocation).
    This file must be handled as SENSITIVE and deleted after verification.
    """
    recipe = build_cyberchef_recipe(key_hex, nonce_hex)
    output_path.write_text(json.dumps(recipe, indent=2))
```

#### CLI Surface

```
forge exfil verify --engagement <id> --bundle <sha256>.enc --emit-recipe
```

- `--emit-recipe` writes `<sha256>_recipe.json` to `~/.forge/tmp/` (registered with `cleanup.py`).
- The operator loads the `.enc` file and the recipe JSON into CyberChef locally.
- Successful decompression confirms round-trip integrity before the operator declares collection
  complete.

> **OPSEC:** The recipe JSON contains the AES key and nonce in hex. Treat it with the same
> sensitivity as the engagement key material. Register it with `cleanup.py` immediately at
> creation. Never transmit it over the network.

#### Anti-Patterns

| Anti-Pattern | Risk | Correct Approach |
|---|---|---|
| Calling `cyberchef-node` as a subprocess during engagement | Process signature visible to EDR on operator host | Use `cyberchef-node` in CI only; operator-facing path is static recipe JSON |
| Storing the recipe file in the engagement DB | Key material in plaintext SQLite row | Write to `~/.forge/tmp/`; age-encrypt; register for cleanup |
| Skipping verification for "small" bundles | Silent corruption goes undetected until Phase 6 | Verification is mandatory regardless of bundle size; enforce at CLI layer |

## Part II — LeakLooker: Post-Exfiltration Monitoring

### 2.1 Rationale

Module 2-F already integrates LeakLooker-style paste monitoring as a **pre-engagement** and
**during-engagement** credential exposure signal (see Chunk 3, §7.7.5). The integration described
here is distinct in purpose: it operates **post-exfiltration**, using fingerprints derived from
confirmed exfil captures to detect whether that data — or derivatives of it — surfaces on public
paste sites. This addresses a specific operational risk: exfiltrated data that appears publicly
could indicate a secondary breach (the target discovered the exfil and published it), a leak
from the operator's own infrastructure, or data resold by a third party on the operator's
collection path.

This is an **operator-facing monitoring capability**, not a target-side capability. All monitoring
requests originate from the operator station, routed through operator-controlled infrastructure.

---

### 2.2 Threat Model

| Scenario | Indicator | Module 5-H Response |
|---------|-----------|---------------------|
| Target discovers exfil and publishes as evidence | File hashes, keyword excerpts appear on paste sites | Alert operator via `paste_exfil_alerts` table |
| Operator infrastructure compromised; data leaked by third party | Hash or keyword match on paste site | Alert operator; flag for immediate OPSEC review |
| Exfil bundle intercepted in transit and posted | Hash match on paste site | Alert operator; confirm integrity of C2 channel |
| False positive (unrelated data matching keyword) | Keyword match but no hash match | Rank alert `LOW`; require operator confirmation |

---

### 2.3 Schema Addition

```sql
-- forge/migrations/009_add_exfil_monitor.sql

CREATE TABLE IF NOT EXISTS exfil_monitor_targets (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    engagement_id   INTEGER NOT NULL REFERENCES engagements(id) ON DELETE CASCADE,
    collection_id   TEXT    NOT NULL,   -- FK to exfil_collections.id
    monitor_type    TEXT    NOT NULL CHECK (monitor_type IN ('hash', 'keyword')),
    monitor_value   TEXT    NOT NULL,   -- SHA-256 hex OR keyword string (max 128 chars)
    created_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    active          INTEGER NOT NULL DEFAULT 1,
    UNIQUE (engagement_id, monitor_type, monitor_value)
);

CREATE TABLE IF NOT EXISTS paste_exfil_alerts (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    engagement_id   INTEGER NOT NULL REFERENCES engagements(id) ON DELETE CASCADE,
    monitor_id      INTEGER NOT NULL REFERENCES exfil_monitor_targets(id),
    paste_url       TEXT    NOT NULL,
    paste_source    TEXT    NOT NULL DEFAULT 'pastebin',
    confidence      TEXT    NOT NULL DEFAULT 'HIGH' CHECK (confidence IN ('HIGH', 'MEDIUM', 'LOW')),
    first_seen_at   TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    raw_snippet     TEXT,            -- First 512 chars ONLY; never full content
    opsec_flag      INTEGER NOT NULL DEFAULT 0,  -- 1 = operator flagged for review
    UNIQUE (engagement_id, monitor_id, paste_url)
);

CREATE INDEX IF NOT EXISTS idx_exfil_alerts_engagement
    ON paste_exfil_alerts (engagement_id, first_seen_at DESC);
```

> **Design invariant:** `raw_snippet` is capped at 512 characters. Full paste content is **never
> stored**. If a hash match is confirmed, the operator is expected to retrieve the paste
> independently via the URL.

### 2.4 Pydantic Models

```python
# forge/phase5/models.py (addition)
from __future__ import annotations
from datetime import datetime
from enum import Enum
from pydantic import BaseModel, Field, field_validator


class MonitorType(str, Enum):
    HASH    = "hash"
    KEYWORD = "keyword"


class ConfidenceLevel(str, Enum):
    HIGH   = "HIGH"
    MEDIUM = "MEDIUM"
    LOW    = "LOW"


class ExfilMonitorTarget(BaseModel):
    engagement_id:  int
    collection_id:  str
    monitor_type:   MonitorType
    monitor_value:  str = Field(max_length=128)
    active:         bool = True

    @field_validator("monitor_value")
    @classmethod
    def validate_value(cls, v: str, info) -> str:
        monitor_type = info.data.get("monitor_type")
        if monitor_type == MonitorType.HASH:
            if len(v) != 64 or not all(c in "0123456789abcdef" for c in v.lower()):
                raise ValueError("Hash monitor_value must be a 64-char lowercase hex SHA-256 digest")
        elif monitor_type == MonitorType.KEYWORD:
            if len(v.strip()) < 6:
                raise ValueError("Keyword monitor_value must be at least 6 characters")
        return v


class PasteExfilAlert(BaseModel):
    engagement_id:  int
    monitor_id:     int
    paste_url:      str
    paste_source:   str = "pastebin"
    confidence:     ConfidenceLevel = ConfidenceLevel.HIGH
    first_seen_at:  datetime = Field(default_factory=datetime.utcnow)
    raw_snippet:    str | None = Field(default=None, max_length=512)
    opsec_flag:     bool = False
```

### 2.5 Core Implementation

```python
# forge/phase5/exfil_monitor.py
"""
Post-exfiltration paste site monitor — Module 5-H extension.

Polls Pastebin (and optionally other paste services) for operator-registered
fingerprints derived from confirmed exfil collections. Runs as a background
daemon thread; does not block the CLI.

Design invariants:
  1. Only SHA-256 hashes and operator-defined keywords are registered.
     File contents are never transmitted to any third party.
  2. Raw snippets are truncated to 512 chars before DB storage.
  3. Hash matching uses substring search on paste content
     (hashes are 64-char strings; collision with arbitrary prose is negligible).
  4. Keyword matching is case-insensitive; minimum 6-char term enforced.
  5. Confidence levels:
       HIGH   — hash match (deterministic)
       MEDIUM — keyword match in a paste with other in-scope signals
       LOW    — keyword match only (no corroborating signals)
  6. Polling is routed through operator-supplied proxy; never direct.
  7. Minimum poll interval: 60 s (Module 2-F floor is 30 s; post-exfil
     monitoring is lower urgency and reduced polling aggression limits
     operator-host signature).
"""
from __future__ import annotations

import logging
import sqlite3
import threading
import time
from dataclasses import dataclass, field
from datetime import datetime
from pathlib import Path
from typing import Optional

import httpx

from forge.phase5.models import ConfidenceLevel, ExfilMonitorTarget, MonitorType, PasteExfilAlert

logger = logging.getLogger(__name__)

PASTEBIN_SCRAPE_URL = "https://scrape.pastebin.com/api_scraping.php"
PASTEBIN_SCRAPE_RAW = "https://scrape.pastebin.com/api_scrape_item.php"
PASTEBIN_RSS_URL    = "https://pastebin.com/rss/"

_SNIPPET_LIMIT      = 512   # characters stored in DB
_MIN_POLL_INTERVAL  = 60    # seconds
_SEEN_KEYS_CAP      = 50_000


@dataclass
class ExfilMonitor:
    engagement_id:   int
    db_path:         Path
    poll_interval:   int   = 120
    pro_account:     bool  = False
    proxy:           Optional[str] = None

    _stop_event:     threading.Event = field(default_factory=threading.Event, init=False)
    _thread:         Optional[threading.Thread] = field(default=None, init=False)
    # OrderedDict used as LRU-capped seen-key store
    _seen_keys:      dict = field(default_factory=dict, init=False)

    def __post_init__(self) -> None:
        if self.poll_interval < _MIN_POLL_INTERVAL:
            logger.warning(
                "ExfilMonitor: poll_interval %d s below minimum %d s; clamping.",
                self.poll_interval, _MIN_POLL_INTERVAL,
            )
            self.poll_interval = _MIN_POLL_INTERVAL

    # ------------------------------------------------------------------
    # Public API
    # ------------------------------------------------------------------

    def start(self) -> None:
        self._thread = threading.Thread(
            target=self._run,
            name=f"ExfilMonitor-eng{self.engagement_id}",
            daemon=True,
        )
        self._thread.start()
        logger.info(
            "ExfilMonitor started (engagement %d, interval %ds)",
            self.engagement_id, self.poll_interval,
        )

    def stop(self) -> None:
        self._stop_event.set()
        if self._thread:
            self._thread.join(timeout=10)
        logger.info("ExfilMonitor stopped (engagement %d)", self.engagement_id)

    # ------------------------------------------------------------------
    # Internal: load targets
    # ------------------------------------------------------------------

    def _load_targets(self, con: sqlite3.Connection) -> list[ExfilMonitorTarget]:
        rows = con.execute(
            """SELECT id, engagement_id, collection_id, monitor_type, monitor_value
               FROM exfil_monitor_targets
               WHERE engagement_id = ? AND active = 1""",
            (self.engagement_id,),
        ).fetchall()
        return [
            ExfilMonitorTarget(
                engagement_id=r[1],
                collection_id=r[2],
                monitor_type=MonitorType(r[3]),
                monitor_value=r[4],
            )
            for r in rows
        ]

    # ------------------------------------------------------------------
    # Internal: paste fetch
    # ------------------------------------------------------------------

    def _fetch_recent_pastes(self, client: httpx.Client) -> list[dict]:
        if self.pro_account:
            try:
                resp = client.get(PASTEBIN_SCRAPE_URL, params={"limit": 100}, timeout=15)
                resp.raise_for_status()
                return resp.json()
            except Exception as exc:
                logger.warning("ExfilMonitor: scrape API error (%s); falling back to RSS", exc)

        # RSS fallback
        try:
            import xml.etree.ElementTree as ET
            resp = client.get(PASTEBIN_RSS_URL, timeout=15)
            resp.raise_for_status()
            root  = ET.fromstring(resp.text)
            items = []
            for item in root.iter("item"):
                link = item.findtext("link") or ""
                key  = link.rstrip("/").split("/")[-1]
                if key:
                    items.append({"key": key, "url": link})
            return items
        except Exception as exc:
            logger.error("ExfilMonitor: RSS fallback error: %s", exc)
            return []

    def _fetch_paste_content(self, client: httpx.Client, key: str) -> Optional[str]:
        try:
            resp = client.get(PASTEBIN_SCRAPE_RAW, params={"i": key}, timeout=15)
            resp.raise_for_status()
            return resp.text
        except Exception as exc:
            logger.debug("ExfilMonitor: failed to fetch paste %s: %s", key, exc)
            return None

    # ------------------------------------------------------------------
    # Internal: seen-key LRU management
    # ------------------------------------------------------------------

    def _mark_seen(self, key: str) -> None:
        if len(self._seen_keys) >= _SEEN_KEYS_CAP:
            # Evict oldest entry (insertion-order dict)
            evicted = next(iter(self._seen_keys))
            del self._seen_keys[evicted]
            logger.debug("ExfilMonitor: _seen_keys cap reached; evicted key %s", evicted)
        self._seen_keys[key] = True

    # ------------------------------------------------------------------
    # Internal: match
    # ------------------------------------------------------------------

    def _match_targets(
        self,
        content: str,
        targets: list[ExfilMonitorTarget],
    ) -> list[tuple[ExfilMonitorTarget, ConfidenceLevel]]:
        content_lower = content.lower()
        results: list[tuple[ExfilMonitorTarget, ConfidenceLevel]] = []
        hash_matched = False

        for target in targets:
            if target.monitor_type == MonitorType.HASH:
                if target.monitor_value.lower() in content_lower:
                    hash_matched = True
                    results.append((target, ConfidenceLevel.HIGH))

        for target in targets:
            if target.monitor_type == MonitorType.KEYWORD:
                if target.monitor_value.lower() in content_lower:
                    level = ConfidenceLevel.MEDIUM if hash_matched else ConfidenceLevel.LOW
                    results.append((target, level))

        return results

    # ------------------------------------------------------------------
    # Internal: persistence
    # ------------------------------------------------------------------

    def _save_alert(
        self,
        con: sqlite3.Connection,
        monitor_id: int,
        paste_url: str,
        paste_source: str,
        confidence: ConfidenceLevel,
        content: str,
    ) -> bool:
        snippet = content[:_SNIPPET_LIMIT]
        try:
            con.execute(
                """INSERT INTO paste_exfil_alerts
                   (engagement_id, monitor_id, paste_url, paste_source, confidence,
                    first_seen_at, raw_snippet, opsec_flag)
                   VALUES (?, ?, ?, ?, ?, ?, ?, 0)
                   ON CONFLICT (engagement_id, monitor_id, paste_url) DO NOTHING""",
                (
                    self.engagement_id,
                    monitor_id,
                    paste_url,
                    paste_source,
                    confidence.value,
                    datetime.utcnow().isoformat(),
                    snippet,
                ),
            )
            con.commit()
            return con.execute("SELECT changes()").fetchone()[0] > 0
        except sqlite3.Error as exc:
            logger.error("ExfilMonitor: DB write error: %s", exc)
            return False

    # ------------------------------------------------------------------
    # Internal: main loop
    # ------------------------------------------------------------------

    def _run(self) -> None:
        transport = httpx.HTTPTransport(proxy=self.proxy) if self.proxy else None
        con       = sqlite3.connect(self.db_path, check_same_thread=False)

        with httpx.Client(transport=transport, follow_redirects=True) as client:
            while not self._stop_event.is_set():
                try:
                    targets = self._load_targets(con)
                    if not targets:
                        logger.debug(
                            "ExfilMonitor: no active targets for engagement %d",
                            self.engagement_id,
                        )
                        self._stop_event.wait(timeout=self.poll_interval)
                        continue

                    for paste in self._fetch_recent_pastes(client):
                        key = paste.get("key", "")
                        if not key or key in self._seen_keys:
                            continue
                        self._mark_seen(key)

                        content = self._fetch_paste_content(client, key)
                        if not content:
                            continue

                        for target, confidence in self._match_targets(content, targets):
                            row = con.execute(
                                """SELECT id FROM exfil_monitor_targets
                                   WHERE engagement_id = ?
                                     AND monitor_type  = ?
                                     AND monitor_value = ?""",
                                (self.engagement_id, target.monitor_type.value, target.monitor_value),
                            ).fetchone()
                            if not row:
                                continue

                            paste_url = paste.get("url", f"https://pastebin.com/{key}")
                            if self._save_alert(con, row[0], paste_url, "pastebin", confidence, content):
                                logger.warning(
                                    "ExfilMonitor: [%s] ALERT — %s match '%s...' at %s",
                                    confidence.value,
                                    target.monitor_type.value.upper(),
                                    target.monitor_value[:16],
                                    paste_url,
                                )

                except Exception as exc:
                    logger.error("ExfilMonitor poll cycle error: %s", exc)

                self._stop_event.wait(timeout=self.poll_interval)

        con.close()
```

### 2.6 Module 5-H CLI Integration

#### Flag Additions

```
forge exfil monitor
  --engagement    <id>           Target engagement (required)
  --monitor-hash  <sha256>       Register a file SHA-256 as a monitoring fingerprint (repeatable)
  --monitor-keyword <term>       Register a keyword derived from exfil data; min 6 chars (repeatable)
  --monitor-interval <seconds>   Poll interval in seconds (default: 120, min: 60)
  --monitor-proxy socks5://...   Proxy for all monitoring traffic (strongly recommended)
  --monitor-pastebin-pro         Use Pastebin Pro scraping API (higher fidelity vs RSS fallback)
  --force-no-proxy               Suppress proxy-absent warning (requires explicit acknowledgement)
```

Multiple `--monitor-hash` and `--monitor-keyword` flags may be provided in a single invocation.
All targets are written to `exfil_monitor_targets` before the daemon starts.

#### Workflow

```bash
# 1. Run exfiltration
forge exfil run \
  --engagement 42 \
  --collector filesystem \
  --window 09:00-17:00 \
  --throttle 512k

# 2. Verify bundle integrity with CyberChef recipe
forge exfil verify \
  --engagement 42 \
  --bundle a3f1c8d2e4b6a9f0c3e7d5b8f2a1e9c4.enc \
  --emit-recipe

# 3. Register fingerprints and start post-exfil monitor
forge exfil monitor \
  --engagement 42 \
  --monitor-hash a3f1c8d2e4b6a9f0c3e7d5b8f2a1e9c4d6b3f0e8c5a2d7b4f1e6c9a3d0b7f2e5 \
  --monitor-keyword "CORP-CONFIDENTIAL-Q4-2025" \
  --monitor-interval 120 \
  --monitor-proxy socks5://127.0.0.1:9050
```

#### Registration Helper

```python
# forge/phase5/exfiltration.py (addition to post-upload handler)

def _register_monitor_targets(
    engagement_id: int,
    collection_id: str,
    db_path: Path,
    hashes: list[str],
    keywords: list[str],
) -> None:
    """
    Persists operator-supplied fingerprints immediately after a confirmed C2 upload.
    Called automatically when --monitor-exfil is set; also callable interactively.
    """
    con = sqlite3.connect(db_path)
    rows = [
        (engagement_id, collection_id, "hash", h)    for h in hashes
    ] + [
        (engagement_id, collection_id, "keyword", k) for k in keywords
    ]
    con.executemany(
        """INSERT OR IGNORE INTO exfil_monitor_targets
           (engagement_id, collection_id, monitor_type, monitor_value)
           VALUES (?, ?, ?, ?)""",
        rows,
    )
    con.commit()
    con.close()
```

### 2.7 OPSEC Constraints

| Risk | Mitigation |
|------|-----------|
| Monitoring requests attributable to the operator | `--monitor-proxy` is required; CLI exits with code `1` if absent and `--force-no-proxy` is not explicitly set |
| Keyword too generic; high false-positive rate | 6-char minimum at Pydantic and CLI layers; `LOW` confidence alerts separated from `HIGH` in Phase 6 report |
| SHA-256 substring collision in paste content | Non-issue at 64 hex chars; probability is astronomically low |
| Monitoring reveals operator existence to target | Monitoring is entirely passive (read-only); risk is limited to operator-infrastructure attribution |
| `_seen_keys` unbounded growth in long engagements | LRU eviction at 50,000 entries using insertion-order dict; eviction events logged at `DEBUG` |
| Daemon not stopped post-engagement | `forge clean --engagement <id>` calls `ExfilMonitor.stop()` before artefact deletion; monitor handle stored in engagement state |
| CyberChef recipe file contains key material | Recipe files registered with `cleanup.py` at creation; deleted with `shred -u` (Linux) / `sdelete` (Windows) on `forge clean` |

---

### 2.8 Confidence Scoring Logic

```
Hash match only          → HIGH    Deterministic; 64-char SHA-256 substring collision negligible
Hash match + keyword     → HIGH    Reinforcing signals; treat as confirmed
Keyword in hash-matched  → MEDIUM  Paste also contains a hash match; elevated from LOW
Keyword only             → LOW     Weak signal; requires operator review before actioning
```

This model must be documented verbatim in the Phase 6 report section header so that analysts
do not treat `LOW` alerts as confirmed secondary breaches without operator review.

### 2.9 Phase 6 Reporting Integration

```python
# forge/phase6/report_generator.py (addition)

def _build_exfil_monitoring_section(engagement_id: int, db_path: Path) -> str:
    con = sqlite3.connect(db_path)
    rows = con.execute(
        """SELECT pea.confidence, pea.paste_source, pea.paste_url,
                  pea.first_seen_at, pea.raw_snippet,
                  emt.monitor_type, emt.monitor_value
           FROM paste_exfil_alerts pea
           JOIN exfil_monitor_targets emt ON emt.id = pea.monitor_id
           WHERE pea.engagement_id = ?
           ORDER BY
               CASE pea.confidence WHEN 'HIGH' THEN 1 WHEN 'MEDIUM' THEN 2 ELSE 3 END,
               pea.first_seen_at DESC""",
        (engagement_id,),
    ).fetchall()
    con.close()

    if not rows:
        return (
            "## Post-Exfiltration Exposure Monitoring\n\n"
            "_No paste-site matches detected during the monitoring window._\n"
        )

    lines = [
        "## Post-Exfiltration Exposure Monitoring\n",
        "> **Confidence key:** "
        "`HIGH` = hash match (deterministic). "
        "`MEDIUM` = keyword in hash-matched paste. "
        "`LOW` = keyword only — requires operator review before actioning.\n",
    ]
    for confidence, source, url, seen_at, snippet, mtype, mvalue in rows:
        masked = (mvalue[:8] + "…" + mvalue[-4:]) if mtype == "hash" else mvalue
        lines.append(f"### [{confidence}] {source} — {seen_at}")
        lines.append(f"- **URL:** {url}")
        lines.append(f"- **Match type:** `{mtype}` — `{masked}`")
        if snippet:
            lines.append(f"- **Snippet (first 200 chars):**\n  ```\n  {snippet[:200]}\n  ```")
        lines.append("")

    return "\n".join(lines)
```

### 2.10 Documentation Addition — Module 5-H

> **Data Leak Monitoring (`forge exfil monitor` / `--monitor-exfil`):**
>
> After a confirmed exfiltration collection, register SHA-256 file hashes and/or operator-defined
> keywords unique to the exfiltrated dataset (e.g., internal document classification strings such
> as `"CORP-CONFIDENTIAL-Q4-2025"`). A background daemon then polls configured paste sites at a
> minimum 60-second interval for any matching content.
>
> Hash fingerprints are derived from individual collected files — pass the SHA-256 from the
> exfil collection manifest. Keyword fingerprints must be specific enough to avoid false positives
> (minimum 6 characters, enforced at the CLI).
>
> Match alerts are stored in `paste_exfil_alerts` and surface in the Phase 6 report under
> **"Post-Exfiltration Exposure Monitoring"**, ranked by confidence level. A `HIGH`-confidence
> alert — a SHA-256 hash detected on a public paste site — warrants immediate OPSEC review and
> notification to engagement stakeholders. `LOW` alerts require operator confirmation before any
> action is taken.
>
> Always route monitoring traffic through `--monitor-proxy` to prevent direct attribution of

## Part III — Cross-Cutting Engineering Requirements (Updated)

### 1. Dry-Run Mode

All Phase 5 modules — including `ExfilMonitor` — must implement a `DryRunContext` that
prevents any network or disk side effects during testing and pre-engagement review:

```python
class DryRunContext:
    def execute(self, cmd: str) -> str:
        click.echo(f"[DRY-RUN] Would execute: {cmd}")
        return ""
    def write_file(self, path: str, content: bytes) -> None:
        click.echo(f"[DRY-RUN] Would write {len(content)} bytes to: {path}")
    def start_monitor(self, monitor: "ExfilMonitor") -> None:
        click.echo(
            f"[DRY-RUN] Would start ExfilMonitor — "
            f"engagement {monitor.engagement_id}, "
            f"interval {monitor.poll_interval}s"
        )
```

In dry-run mode, `ExfilMonitor` logs all targets that would be registered and all pastes that
would be fetched, without making any network requests or DB writes.

### 2. Mandatory `cleanup.py` Integration

Every artefact created by Phase 5 — including `ExfilMonitor` daemon handles, CyberChef recipe
JSON files, and exfil staging directories — must be registered with `cleanup.py` at creation time:

```python
from forge.cleanup import CleanupRegistry

registry = CleanupRegistry.get()

# Monitor daemon teardown
registry.register(
    artefact_type="daemon",
    handle=monitor,          # ExfilMonitor instance; cleanup.py calls monitor.stop()
    cleanup_cmd=None,
    module="5-H",
    engagement_id=ctx.engagement_id,
)

# CyberChef recipe file — contains key material; secure delete required
registry.register(
    artefact_type="file",
    path=str(recipe_path),
    cleanup_cmd=f"shred -u {recipe_path}",   # Linux; sdelete on Windows
    module="5-H",
    engagement_id=ctx.engagement_id,
)
```

`forge clean --engagement <id>` must call `ExfilMonitor.stop()` on any running instance
**before** proceeding with artefact deletion to avoid race conditions on the engagement DB.
