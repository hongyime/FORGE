# Project Context: FORGE Toolkit v7.1

FORGE v7.1 is a modular, CPU-optimised, full-spectrum offensive security platform for authorised
red team operations and penetration testing. It covers the complete kill-chain from offline
knowledge base construction through reconnaissance, OSINT credential intelligence, evasion,
exploit correlation, post-exploitation, and LLM-assisted reporting. All modules are
deterministic, rule-based, and offline-first where possible. The local LLM (Qwen2.5-1.5B via
`llama-cpp-python`) serves exclusively as a post-engagement report synthesis aid.

| Phase | Name                          | Description                                                                       |
|-------|-------------------------------|-----------------------------------------------------------------------------------|
| 0     | Knowledge Base                | Offline ETL of LOLBAS, GTFOBins, LOTS, MalAPI, Exploit-DB, NVD CVE feeds         |
| 1     | Reconnaissance                | Engagement wizard, subdomain enum, port scan, email harvesting, resume detection  |
| 2     | OSINT & Credential Intelligence | Breach DB query, credential validation/spray, DeHashed, XposedOrNot, theHarvester |
| 3     | Evasion & Payload Generation  | 6-criterion obfuscation matrix, encoding chain, HTML smuggling                    |
| 4     | Exploit Correlation           | Version parser, searchsploit integration, CVSS enrichment                         |
| 5     | Post-Exploitation             | Reverse shell, C2 beacon, exfiltration, persistence, lateral movement             |
| 6     | LLM-Assisted Reporting        | Qwen2.5-1.5B report synthesis, validator, Phase 2+5 context integration           |

**This chunk covers Phase 0 (Knowledge Base)**, which provides the offline intelligence
foundation consumed by all subsequent phases. Phase 0 data is synced exclusively during
pre-engagement windows; **no network access occurs during live operations**.

The engagement database schema, Pydantic models, and shared utilities are documented in Chunk 0.

## 5. PHASE 0: OFFLINE KNOWLEDGE BASE

### 5.1 Purpose and Scope

Phase 0 is the **sole network-active phase** in FORGE's pre-engagement lifecycle. Its
responsibility is twofold:

1. **Exploit Intelligence:** Populate queryable offline databases of known living-off-the-land
   binaries (LOLBins), GTFOBins, trusted hosting sites (LOTS), malicious API patterns (MalAPI),
   vulnerable driver signatures (LOLDrivers), and CVE/exploit mappings. These are consumed by
   Phases 1, 3, and 4 for technique selection and exploit correlation.

2. **Evasion Lore:** Curate OS-specific lists of legitimate system artifacts — scheduled task
   names, cron paths, named pipe identifiers, service names — that Phase 5 modules use to blend
   operator-generated artifacts into the noise floor of a real target system. This is distinct from
   exploit intelligence; it encodes *how legitimate systems look* rather than *how they can be
   abused*.

Both roles are populated during the same ETL run and stored in `lolbas.db`. No data is written
to the engagement state store at this stage; Phase 0 outputs are **read-only reference
databases**, accessed at query time by downstream modules.

### 5.2 Data Sources and Target Databases

| Source                  | Format          | Target DB            | Table(s)                              | Refresh Cadence |
|-------------------------|-----------------|----------------------|---------------------------------------|-----------------|
| LOLBAS (JSON feed)      | JSON            | `lolbas.db`          | `lolbas`, `lolbas_fts`               | Weekly          |

| MalAPI.io               | JSON feed       | `lolbas.db`          | `malapi`                              | Weekly          |
| LOLDrivers              | JSON feed       | `lolbas.db`          | `loldrivers`                          | Weekly          |
| Exploit-DB (CSV offline)| CSV             | `exploit_cache.db`   | `exploits`, `exploits_fts`            | On-demand       |
| NVD CVE feed (JSON)     | JSON (gzipped)  | `nvd_cache.db`       | `cve`, `cve_fts`, `cvss_scores`       | Weekly          |

**Key constraints:**
- All three databases (`lolbas.db`, `exploit_cache.db`, `nvd_cache.db`) are opened **read-only**
  (`PRAGMA query_only = ON`) by all phases except Phase 0 itself.
- WAL mode is **not** used on these databases; they are write-once-read-many. Standard journal
  mode is sufficient and avoids WAL file leakage on operator systems.
- Database files must be `age`-encrypted at rest consistent with engagement DB policy (Chunk 0
  §4.3) if stored alongside engagement data.

#### 5.3.1 Evasion Artifact Population

Phase 0 ETL now includes a dedicated evasion artifact curation step, executed **after** LOLBin
population and **before** the staleness report is written. This step populates four tables in
`lolbas.db` that are consumed exclusively by Phase 5 modules:

| Table                  | OS      | Consumer    | Purpose                                                    |
|------------------------|---------|-------------|------------------------------------------------------------|
| `schtasks_legit_names` | Windows | Module 5-I  | Plausible scheduled task names drawn from real Windows systems |
| `cron_legit_paths`     | Linux   | Module 5-I  | Common cron job paths and command patterns from real Linux configs |
| `plausible_pipe_names` | Windows | Module 5-J  | Named pipe identifiers seen on real Windows hosts (for SMB exec evasion) |
| `legit_service_names`  | Windows | Module 5-I  | Display names and binary paths of real Windows services for service-based persistence |

**Schema — `schtasks_legit_names`:**
```sql
CREATE TABLE IF NOT EXISTS schtasks_legit_names (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT NOT NULL UNIQUE,           -- e.g. "MicrosoftEdgeUpdateTaskMachineCore"
    description TEXT,                           -- Human-readable description (mirrors real task)
    trigger_pattern TEXT,                       -- Cron-like or interval string for mimicry
    author      TEXT,                           -- Task author field value
    stealth_rank INTEGER DEFAULT 5,             -- 1 (high stealth) to 10 (low stealth)
    source      TEXT DEFAULT 'curated'          -- 'curated' | 'lolbas_derived'
);
CREATE INDEX IF NOT EXISTS idx_schtasks_stealth ON schtasks_legit_names(stealth_rank);
```

**Schema — `cron_legit_paths`:**
```sql
CREATE TABLE IF NOT EXISTS cron_legit_paths (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    path        TEXT NOT NULL UNIQUE,           -- e.g. "/etc/cron.daily/logrotate"
    command_pattern TEXT,                       -- Typical command invoked at this path
    distro_family TEXT,                         -- 'debian' | 'rhel' | 'arch' | 'any'
    stealth_rank INTEGER DEFAULT 5
);
```

**Schema — `plausible_pipe_names`:**
```sql
CREATE TABLE IF NOT EXISTS plausible_pipe_names (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    pipe_name   TEXT NOT NULL UNIQUE,           -- e.g. "\\pipe\\svcctl", "\\pipe\\lsarpc"
    owning_service TEXT,                        -- Legitimate service that creates this pipe
    sysmon_monitored INTEGER DEFAULT 0,         -- 1 if commonly in Sysmon Event ID 17/18 watchlists
    stealth_rank INTEGER DEFAULT 5
);
CREATE INDEX IF NOT EXISTS idx_pipe_sysmon ON plausible_pipe_names(sysmon_monitored, stealth_rank);
```

**Schema — `legit_service_names`:**
```sql
CREATE TABLE IF NOT EXISTS legit_service_names (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    display_name TEXT NOT NULL,                 -- e.g. "Windows Update"
    service_name TEXT NOT NULL UNIQUE,          -- Short name: "wuauserv"
    binary_path  TEXT,                          -- Typical ImagePath value
    start_type   TEXT,                          -- 'auto' | 'demand' | 'disabled'
    stealth_rank INTEGER DEFAULT 5
);
```

**Population logic:**

Evasion artifact tables are populated from a **versioned, curated YAML file** shipped with
FORGE (`forge/phase0/evasion_artifacts.yaml`). This is intentional: unlike LOLBin data, which
benefits from live upstream feeds, evasion artifact lore changes slowly and requires human
curation to ensure accuracy and stealth quality. Operators may extend the YAML file to add
target-environment-specific entries before a specific engagement.
```yaml
# forge/phase0/evasion_artifacts.yaml (excerpt)

    description: "Keeps Microsoft Edge up to date"
    trigger_pattern: "PT1H"           # Every hour
    author: "Microsoft Corporation"
    stealth_rank: 2
  - name: "OneDrive Reporting Task-S-1-5-21"
    description: "OneDrive usage telemetry reporting"
    trigger_pattern: "P1D"
    author: "Microsoft Corporation"
    stealth_rank: 3

plausible_pipe_names:
  - pipe_name: "\\pipe\\svcctl"
    owning_service: "Service Control Manager"
    sysmon_monitored: 1
    stealth_rank: 6
  - pipe_name: "\\pipe\\lsarpc"
    owning_service: "Local Security Authority"
    sysmon_monitored: 1
    stealth_rank: 5
  - pipe_name: "\\pipe\\browser"
    owning_service: "Computer Browser"
    sysmon_monitored: 0
    stealth_rank: 2

cron_legit_paths:
  - path: "/etc/cron.daily/logrotate"
    command_pattern: "/usr/sbin/logrotate /etc/logrotate.conf"
```

**ETL function (Phase 0 pipeline integration):**
```python
# forge/phase0/etl/evasion_artifacts.py

import sqlite3
import yaml
from pathlib import Path

ARTIFACT_YAML = Path(__file__).parent.parent / "evasion_artifacts.yaml"

TABLES = {
    "schtasks_legit_names": [
        "name", "description", "trigger_pattern", "author", "stealth_rank", "source"
    ],
    "cron_legit_paths": [
        "path", "command_pattern", "distro_family", "stealth_rank"
    ],
    "plausible_pipe_names": [
        "pipe_name", "owning_service", "sysmon_monitored", "stealth_rank"
    ],
    "legit_service_names": [
        "display_name", "service_name", "binary_path", "start_type", "stealth_rank"
    ],
}

def populate_evasion_artifacts(db_path: Path) -> dict[str, int]:
    """
    Load curated evasion artifact YAML and upsert into lolbas.db.
    Returns a dict of {table_name: rows_inserted}.
    Idempotent: uses INSERT OR IGNORE to avoid duplicates on re-run.
    """
    data = yaml.safe_load(ARTIFACT_YAML.read_text())
    counts: dict[str, int] = {}

    with sqlite3.connect(db_path) as conn:
        conn.execute("PRAGMA foreign_keys = ON")
        for table, columns in TABLES.items():
            rows = data.get(table, [])
            if not rows:
                counts[table] = 0
                continue
            placeholders = ", ".join("?" * len(columns))
            col_list = ", ".join(columns)
            sql = (
                f"INSERT OR IGNORE INTO {table} ({col_list}) "
                f"VALUES ({placeholders})"
            )
            values = [
                tuple(row.get(col) for col in columns) for row in rows
            ]
            conn.executemany(sql, values)
            counts[table] = len(values)
        conn.commit()

    return counts
```

This function is called from the main Phase 0 ETL orchestrator
(`forge/phase0/etl/__init__.py`) after LOLBin normalisation completes:
```python
# forge/phase0/etl/__init__.py (relevant excerpt)

from forge.phase0.etl.evasion_artifacts import populate_evasion_artifacts

def run_phase0_etl(db_path: Path, console: Console) -> None:
    # ... (v5.0 ETL steps: LOLBAS, GTFOBins, LOTS, MalAPI, LOLDrivers, NVD, Exploit-DB)

    # v7.1 addition: evasion artifact curation
    console.print("[bold cyan]Populating evasion artifact tables...[/bold cyan]")
    counts = populate_evasion_artifacts(db_path)
    for table, n in counts.items():
        console.print(f"  {table}: {n} rows inserted")
    console.print("[green]Evasion artifact population complete.[/green]")
```

#### 5.3.2 Staleness and Re-sync Behaviour

Evasion artifact tables are **not** subject to the automated staleness check applied to live
upstream feeds (LOLBAS, NVD, etc.). They are populated on every ETL run using `INSERT OR IGNORE`,
making re-population idempotent. Operator-added entries in the YAML survive across re-runs.

To force a full rebuild (e.g., after `evasion_artifacts.yaml` is updated), operators run:
```bash
forge update-kb --force-evasion-artifacts
```

This executes `DELETE FROM <table>` for all four evasion artifact tables before re-populating,
ensuring stale curated data does not persist.

### 5.4 Cross-Phase Consumption Map

Phase 0 outputs are **read-only at all times during live engagement**. The following table
documents every downstream consumer, the specific table queried, and the query pattern used.

| Phase | Module   | DB                  | Table(s) Queried              | Query Pattern                                      |
|-------|----------|---------------------|-------------------------------|----------------------------------------------------|
| 1     | Recon    | `lolbas.db`         | `lolbas`, `lots_sites`        | FTS5 keyword search by technique category          |
| 3     | Evasion  | `lolbas.db`         | `lolbas`, `lots_sites`, `malapi` | LOLBin selection by OS + category; LOTS host picker |
| 4     | Exploit  | `exploit_cache.db`  | `exploits`, `exploits_fts`    | FTS5 + product/version filter; searchsploit bridge |
| 4     | Exploit  | `nvd_cache.db`      | `cve`, `cvss_scores`          | CVE ID lookup; CVSS enrichment join                 |
| 5-G   | C2 Beacon| `lolbas.db`         | `plausible_pipe_names`        | `WHERE sysmon_monitored = 0 ORDER BY stealth_rank ASC LIMIT 1` |
| 5-I   | Persistence | `lolbas.db`      | `schtasks_legit_names`, `cron_legit_paths`, `legit_service_names` | `ORDER BY RANDOM() LIMIT 1` (names); `ORDER BY stealth_rank ASC` (ranked selection) |
| 5-J   | Lateral  | `lolbas.db`         | `plausible_pipe_names`        | `WHERE sysmon_monitored = 0 ORDER BY stealth_rank ASC` |

**Query abstraction:** All Phase 0 queries are routed through `forge/phase0/kb_query.py`, which
manages the read-only connection pool and exposes typed query functions. No downstream module
opens `lolbas.db` directly.
```python
# forge/phase0/kb_query.py (interface)

from pathlib import Path
import sqlite3
from functools import lru_cache
from typing import Optional

_KB_PATH: Optional[Path] = None

def init_kb(db_path: Path) -> None:
    """Call once at startup. Sets the read-only KB path for all query functions."""
    global _KB_PATH
    _KB_PATH = db_path

@lru_cache(maxsize=64)
def get_schtask_name(stealth_rank_max: int = 5) -> str:
    """Return a random high-stealth scheduled task name from the KB."""
    with _ro_conn() as conn:
        row = conn.execute(
            "SELECT name FROM schtasks_legit_names "
            "WHERE stealth_rank <= ? ORDER BY RANDOM() LIMIT 1",
            (stealth_rank_max,)
        ).fetchone()
    if not row:
        raise KBQueryError("schtasks_legit_names table is empty — run `forge update-kb`")
    return row[0]

@lru_cache(maxsize=32)
def get_pipe_name(avoid_sysmon: bool = True) -> str:
    """Return a plausible named pipe identifier for SMB operations."""
    sysmon_filter = "AND sysmon_monitored = 0" if avoid_sysmon else ""
    with _ro_conn() as conn:
        row = conn.execute(
            f"SELECT pipe_name FROM plausible_pipe_names "
            f"WHERE 1=1 {sysmon_filter} ORDER BY stealth_rank ASC LIMIT 5",
        ).fetchall()
    if not row:
        raise KBQueryError("plausible_pipe_names table is empty — run `forge update-kb`")
    import random
    return random.choice(row)[0]

def get_cron_path(distro_family: str = "any", stealth_rank_max: int = 4) -> str:
    """Return a plausible cron path for Linux persistence."""
    with _ro_conn() as conn:
        row = conn.execute(
            "SELECT path FROM cron_legit_paths "
            "WHERE (distro_family = ? OR distro_family = 'any') "
            "AND stealth_rank <= ? ORDER BY RANDOM() LIMIT 1",
            (distro_family, stealth_rank_max)
        ).fetchone()
    if not row:
        raise KBQueryError(f"No cron_legit_paths for distro '{distro_family}'")
    return row[0]

def _ro_conn() -> sqlite3.Connection:
    if _KB_PATH is None:
        raise KBQueryError("KB not initialised — call init_kb() at startup")
    conn = sqlite3.connect(f"file:{_KB_PATH}?mode=ro", uri=True)
    conn.row_factory = sqlite3.Row
    return conn

class KBQueryError(RuntimeError):
    pass
```

> **Anti-pattern:** Never pass raw strings from `kb_query` functions directly into shell command
> templates without validation. All LOLBin names and artifact strings must be validated against a
> `re.fullmatch(r'[\w\s\-\.\\]+', value)` allowlist before interpolation into Jinja2 templates.

### 5.5 FTS5 Index Strategy

Full-text search on LOLBin and exploit descriptions is implemented using SQLite FTS5 virtual
tables with `content=` pointing to the base table. This avoids data duplication while enabling
fast ranked search.
```sql
-- lolbas.db (excerpt)
CREATE VIRTUAL TABLE IF NOT EXISTS lolbas_fts USING fts5(
    name, description, use_case, mitre_technique,
    content='lolbas', content_rowid='id'
);

-- Trigger to keep FTS index current during ETL inserts
CREATE TRIGGER lolbas_ai AFTER INSERT ON lolbas BEGIN
    INSERT INTO lolbas_fts(rowid, name, description, use_case, mitre_technique)
    VALUES (new.id, new.name, new.description, new.use_case, new.mitre_technique);
END;
```

Ranked search is exposed via `kb_query.search_lolbas(query: str, os_filter: str) -> list[dict]`,
which uses the FTS5 `bm25()` ranking function for relevance ordering.

### 5.6 Operational Security Notes for Phase 0

| Risk                                        | Mitigation                                                                                       |
|---------------------------------------------|--------------------------------------------------------------------------------------------------|
| ETL HTTP traffic leaks operator identity    | All ETL requests route through `curl_cffi` with randomised User-Agent; Tor/proxy support planned |
| NVD/Exploit-DB feeds reveal research focus  | ETL always fetches **full** feeds, not targeted queries; no per-CVE lookups during engagement    |
| `lolbas.db` forensic artifact on operator box | Store under encrypted volume; `forge clean --kb` zeroes and removes all Phase 0 databases       |
| Upstream feed tampering (supply chain)      | SHA-256 manifest checked post-download; ETL aborts on hash mismatch                             |
| Evasion YAML committed to version control   | `evasion_artifacts.yaml` excluded from `.gitignore` by default; operators must explicitly add    |

**Key VCR pattern for ETL tests:**
```python
# tests/phase0/test_evasion_artifact_etl.py

import pytest
from pathlib import Path
from forge.phase0.etl.evasion_artifacts import populate_evasion_artifacts

def test_populate_idempotent(tmp_path: Path, kb_schema_db: Path):
    """Running ETL twice must not duplicate rows."""
    counts_first = populate_evasion_artifacts(kb_schema_db)
    counts_second = populate_evasion_artifacts(kb_schema_db)
    assert counts_first == counts_second  # INSERT OR IGNORE: same rows, same count

def test_empty_yaml_section_is_handled(tmp_path: Path, kb_schema_db: Path, monkeypatch):
    """ETL must not raise when a YAML section is absent."""
    monkeypatch.setattr(
        "forge.phase0.etl.evasion_artifacts.ARTIFACT_YAML",
        tmp_path / "empty.yaml"
    )
    (tmp_path / "empty.yaml").write_text("schtasks_legit_names: []\n")
    counts = populate_evasion_artifacts(kb_schema_db)
    assert counts["schtasks_legit_names"] == 0
```
