# Project Context: FORGE Toolkit v7.1

FORGE v7.1 is a modular, CPU-optimised, full-spectrum offensive security platform for authorised red team operations and penetration testing. It covers the complete kill-chain from offline knowledge base construction through reconnaissance, OSINT credential intelligence, evasion, exploit correlation, post-exploitation, and LLM-assisted reporting. All modules are deterministic, rule-based, and offline-first where possible. The local LLM (Qwen2.5-1.5B via `llama-cpp-python`) serves exclusively as a post-engagement report synthesis aid.

| Phase | Name | Description |
|-------|------|-------------|
| 0 | Knowledge Base | Offline ETL of LOLBAS, GTFOBins, LOTS, MalAPI, exploit-DB, NVD CVE feeds |
| 1 | Reconnaissance | Engagement wizard, subdomain enum, port scan, email harvesting, resume detection |
| 2 | OSINT & Credential Intelligence | Breach DB query, credential validation/spray, DeHashed, XposedOrNot, theHarvester |
| 3 | Evasion & Payload Generation | 6-criterion obfuscation matrix, encoding chain, HTML smuggling |
| 4 | Exploit Correlation | Version parser, searchsploit integration, CVSS enrichment |
| 5 | Post-Exploitation | Reverse shell, C2 beacon, exfiltration, persistence, lateral movement |
| 6 | LLM-Assisted Reporting | Qwen2.5-1.5B report synthesis, validator, Phase 2+5 context integration |

**This chunk covers the project-wide foundation**: executive summary, architecture, full project scaffold, complete data schemas, technology stack, CI/CD pipeline, testing strategy, anti-patterns catalogue, glossary, and capability summary. All other chunks depend on the schemas, Pydantic models, and shared utilities documented here.

> **Note on v5.0 references:** This document contains references to v5.0 sections. Those sections are not reproduced here; they are part of the original v5.0 PRD and are left as placeholders.
> **Planning addendum:** Competitive benchmark and expansion roadmap is tracked in `competitive_gap_plan_sqlmap_skipfish_autorecon.md`.

### Key Changes in v7.0

- **Phase renumbering:** Decimal phases (1.5, 3.5) eliminated. All phases now use consecutive integers 0–6. See §1.3.
- **Module label prefixing:** All module identifiers carry a phase prefix (e.g., `2-A`, `5-F`) for unambiguous cross-referencing.
- **Blue team evasion (Phase 5):** Every Phase 5 module now includes a dedicated *Blue Team Countermeasures & Evasion* subsection specifying detection vectors, operator mitigations, and implementation requirements.
- **Architecture and CLI references:** All `forge phase1_5/` and `forge phase3_5/` path references updated to `forge/phase2/` and `forge/phase5/` respectively.
- **Schema and model references:** All Pydantic model and DB table references updated to reflect new phase numbering.

### Key Changes in v7.1

- **Evasion assertion criterion (§1.4):** A measurable success criterion for evasion technique validity — every Phase 5 module must have at least one test that asserts the absence of a banned signature pattern in generated artifacts.
- **`LateralMovementCredential` model (§4.4):** Typed Pydantic v2 model for credentials passed to Module 5-J, covering password, Kerberos ccache, and certificate auth paths. Eliminates the untyped `cred` dict previously used in `lateral_movement.py`.
- **External tool version pinning (§13.3):** Minimum tested versions added for all external binary dependencies. Docker container references added for CI reproducibility.
- **Evasion assertion tests (§15.2):** New `tests/opsec/test_evasion_assertions.py` file and pattern-based assertions demonstrating the evasion criterion in practice.

## 1. EXECUTIVE SUMMARY

### 1.1 Project Vision

FORGE v7.1 is a modular, CPU-optimised, full-spectrum offensive security platform for authorised red team operations and penetration testing. The platform covers the complete kill-chain from offline knowledge base construction through reconnaissance, OSINT credential intelligence, evasion, exploit correlation, post-exploitation, and LLM-assisted reporting.

All modules remain deterministic, rule-based, and offline-first where possible. The local LLM (Qwen2.5-1.5B via `llama-cpp-python`) serves exclusively as a post-engagement report synthesis aid.

### 1.2 Core Objectives

| Objective | Mechanism |
|-----------|-----------|
| Interactive CLI | `questionary` + `Rich` + `Click` |
| Rule-Based Automation | Scoring matrices, template engines, lookup tables |
| Minimal LLM | `llama-cpp-python` Qwen2.5-1.5B Q4_K_M, Phase 6 only |
| State Store | SQLite WAL mode, Pydantic v2 validation |
| Zero External Deps at Runtime | Offline knowledge base, local exploit/agent/breach caches |
| OPSEC | Memory-safe credentials, history sanitisation, artifact cleanup |
| OSINT Intelligence | Phase 2 Modules 2-A through 2-J |
| Cloud Vulnerability Discovery | Phase 4 Modules 4-D through 4-G (IDOR, Firebase, Supabase) |
| Post-Exploitation | Phase 5 Modules 5-F through 5-J |
| Scope Enforcement | All Phase 2, Phase 4 (cloud/web), and Phase 5 modules gate on engagement scope |
| Blue Team Evasion | Per-module countermeasures: traffic blending, process injection, fileless techniques |

### 1.3 Phase Architecture (v7.1 — Linear Numbering)

| Phase | Name | Modules | Former Label |
|-------|------|---------|--------------|
| 0 | Knowledge Base | — | Phase 0 |
| 1 | Reconnaissance | — | Phase 1 |
| 2 | OSINT & Credential Intelligence | 2-A, 2-B, 2-C, 2-D, 2-E, 2-F, 2-G, 2-H, 2-I, 2-J | Phase 1.5 |
| 3 | Evasion & Payload Generation | — | Phase 2 |
| 4 | Exploit Correlation & Vulnerability Discovery | 4-D, 4-E, 4-F, 4-G | Phase 3 |
| 5 | Post-Exploitation | 5-F, 5-G, 5-H, 5-I, 5-J | Phase 3.5 |
| 6 | LLM-Assisted Reporting | — | Phase 4 |

### 1.4 Success Criteria

| Criterion | Target |
|-----------|--------|
| Recon → full kill-chain pipeline | 22–26 weeks |
| Menu interaction latency | < 1 s |
| Long-running task crash recovery | Zero data loss — incremental DB writes every 10 results |
| External API calls during engagement | Zero (except pre-engagement OSINT sync) |
| LLM report generation | 30–60 s on 4-core CPU |
| Test coverage | ≥ 75% |
| Artifact cleanup | Complete on `forge clean --engagement <id>` |
| Scope bypass prevention | Every Phase 2 and Phase 5 action blocked if target not in scope |
| Credential plaintext exposure | Zero — all stored via `age`-encrypted `password_plaintext_enc` |
| Audit completeness | 100% of credential validation and post-exploitation actions logged |
| Blue team evasion | All Phase 5 modules implement at minimum one active detection-bypass technique per blue team vector |
| **Evasion assertion tests** | **For each Phase 5 module, ≥ 1 unit or integration test asserts that the generated artifact does not contain a banned signature pattern (e.g., `TCPClient` in PowerShell output, port `4444` as a literal string, `/dev/tcp` in bash output). Tests must fail if the banned pattern is present.** |

> **Rationale for evasion assertion criterion:** Functional tests confirm that code executes; evasion assertion tests confirm that output is operationally safe. These are orthogonal concerns and must be tracked independently. See §15.2 for canonical implementations.

## 4. DATA SCHEMAS (v7.1 — COMPLETE)

### 4.1 Extended `credentials` Table

```sql
ALTER TABLE credentials ADD COLUMN validated          INTEGER DEFAULT 0;
ALTER TABLE credentials ADD COLUMN validated_service  TEXT;
ALTER TABLE credentials ADD COLUMN validated_host     TEXT;
ALTER TABLE credentials ADD COLUMN validated_at       TIMESTAMP;
ALTER TABLE credentials ADD COLUMN validation_error   TEXT;

CREATE INDEX IF NOT EXISTS idx_creds_validated ON credentials(validated);

CREATE TABLE IF NOT EXISTS credentials (
    id                     INTEGER PRIMARY KEY,
    engagement_id          INTEGER NOT NULL REFERENCES engagements(id),
    email                  TEXT NOT NULL,
    password_hash          TEXT,
    password_plaintext_enc TEXT,
    breach_name            TEXT,
    breach_date            TIMESTAMP,
    source                 TEXT,
    confidence             TEXT CHECK(confidence IN ('confirmed','likely','possible')),
    discovered_at          TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    validated              INTEGER DEFAULT 0,
    validated_service      TEXT,
    validated_host         TEXT,
    validated_at           TIMESTAMP,
    validation_error       TEXT
);
```

```python
# NEW in v7.1 — LateralMovementCredential (Module 5-J)
# ---------------------------------------------------------------------------
# Replaces the untyped `cred` dict previously passed to lateral_movement.execute().
# Exactly one of (password, ccache_path, cert_path+key_path) must be supplied,
# enforced by the model validator below.
# ---------------------------------------------------------------------------

class LateralMovementCredential(BaseModel):
    """Typed credential container for Module 5-J lateral movement operations.

    Auth type semantics:
      'password'    — NTLM/plaintext; password field required.
      'kerberos'    — Pass-the-Ticket; ccache_path must point to a valid ccache file.
      'certificate' — PKINIT / Schannel; cert_path and key_path both required.

    Security note: password is SecretStr — never log, never serialise to JSON
    without explicit .get_secret_value() call. ccache files must be treated as
    equivalent to plaintext credentials and cleaned up via forge clean.
    """
    model_config = ConfigDict(extra="forbid")

    credential_id: int
    username:      str
    domain:        Optional[str] = None

    # Auth material — only one group should be populated (validated below)
    password:      Optional[SecretStr] = None          # 'password' auth
    ccache_path:   Optional[Path]      = None          # 'kerberos' PTT
    cert_path:     Optional[Path]      = None          # 'certificate' PKINIT
    key_path:      Optional[Path]      = None          # 'certificate' private key

    auth_type: Literal['password', 'kerberos', 'certificate'] = 'password'

    @field_validator('ccache_path', 'cert_path', 'key_path', mode='before')
    @classmethod
    def coerce_to_path(cls, v: object) -> Optional[Path]:
        return Path(v) if v is not None else None

    @field_validator('auth_type')
    @classmethod
    def validate_auth_material(cls, v: str, info: object) -> str:
        data = info.data  # type: ignore[attr-defined]
        if v == 'password' and not data.get('password'):
            raise ValueError("auth_type='password' requires the password field.")
        if v == 'kerberos' and not data.get('ccache_path'):
            raise ValueError("auth_type='kerberos' requires ccache_path.")
        if v == 'certificate' and not (data.get('cert_path') and data.get('key_path')):
            raise ValueError("auth_type='certificate' requires both cert_path and key_path.")
        return v

    def get_password(self) -> Optional[str]:
        """Return plaintext password. Caller must `del` the result immediately after use."""
        return self.password.get_secret_value() if self.password else None
```

**Version enforcement in Python wrappers:**

For tools invoked via `subprocess`, validate the detected version at startup and raise `ToolVersionError` if the minimum is not met:

```python
# forge/utils/tool_version.py
import re
import subprocess
from packaging.version import Version

class ToolVersionError(RuntimeError):
    pass

def assert_tool_version(binary: str, min_version: str, version_flag: str = "--version") -> str:
    """Run `binary --version`, parse semver, raise ToolVersionError if below minimum."""
    try:
        raw = subprocess.check_output([binary, version_flag], stderr=subprocess.STDOUT, text=True)
    except FileNotFoundError:
        raise ToolVersionError(f"{binary!r} not found on PATH.")
    match = re.search(r"(\d+\.\d+[\.\d]*)", raw)
    if not match:
        raise ToolVersionError(f"Could not parse version from {binary!r} output: {raw[:120]!r}")
    detected = Version(match.group(1))
    if detected < Version(min_version):
        raise ToolVersionError(
            f"{binary!r} version {detected} is below minimum required {min_version}."
        )
    return str(detected)
```

Usage in `forge/phase2/theharvester.py`:

```python
from forge.utils.tool_version import assert_tool_version, ToolVersionError

class TheHarvesterWrapper:
    BINARY      = "theHarvester"
    MIN_VERSION = "4.0.0"

    def __init__(self) -> None:
        assert_tool_version(self.BINARY, self.MIN_VERSION)
```

> **Long-term recommendation:** For engagements where operator control over the host system is limited, package `theHarvester` and `xfreerdp` as Docker containers and invoke them via `docker run --rm`. The `assert_tool_version` check can then target the container tag rather than the host binary, providing absolute version isolation without requiring operator root access on the engagement machine.

### 15.2 Key Test Cases (v7.1 additions)

#### Evasion Assertion Tests — `tests/opsec/test_evasion_assertions.py`

> **Design principle:** These tests are *negative* assertions — they pass only when a banned pattern is *absent* from the generated artifact. A test failure means a signature has leaked into output, which is an operational defect, not a functional one. Treat failures with the same severity as a scope gate bypass.

```python
# tests/opsec/test_evasion_assertions.py
"""
Evasion assertion tests (v7.1).

Each test validates that a Phase 5 generator does NOT embed a known-bad
signature pattern into its output. These complement functional tests; they
do not replace them.

Banned pattern rationale:
  TCPClient     — PowerShell class name; detected by AMSI/EDR string scan.
  4444          — Default Metasploit listener port; flagged by IDS rules.
  /dev/tcp      — Bash built-in redirection; detected by shell-based EDR.
  nc -e         — Netcat execute flag; blocked and alerted by most EDR.
  wget|curl     — Raw downloader invocation; detected by SIEM process rules.
  cmd.exe /c    — Lateral movement exec prefix; Sysmon Event ID 1 pattern.
"""

import re
import pytest
from forge.phase5.reverse_shell import ReverseShellGenerator
from forge.phase5.c2_generator import C2Generator, gaussian_sleep
from forge.phase5.persistence import PersistenceGenerator
from forge.phase5.lateral_movement import LateralMovementExecutor, _check_time_window
from forge.models.pydantic_models import LateralMovementCredential
import statistics
from datetime import time as dtime
import unittest.mock as mock


# ---------------------------------------------------------------------------
# Module 5-F — Reverse Shell Generator
# ---------------------------------------------------------------------------

POWERSHELL_BANNED = re.compile(r"TCPClient", re.IGNORECASE)
PORT_BANNED        = re.compile(r"\b4444\b")
BASH_BANNED        = re.compile(r"/dev/tcp")
NC_EXEC_BANNED     = re.compile(r"nc\s+-e", re.IGNORECASE)


def test_powershell_shell_no_TCPClient_in_encoded_output(tmp_kb_db):
    """Encoded PowerShell output must not contain the literal class name 'TCPClient'.
    The template is required to alias or obfuscate this type name before encoding."""
    gen = ReverseShellGenerator(tmp_kb_db)
    result = gen.generate("10.0.0.1", 443, "powershell", tls=True)
    assert result.encoded_cmd is not None, "encoded_cmd must be populated for powershell type"
    assert not POWERSHELL_BANNED.search(result.encoded_cmd), (
        "Banned pattern 'TCPClient' found in encoded PowerShell output. "
        "Template obfuscation is insufficient."
    )


def test_no_shell_type_emits_port_4444(tmp_kb_db):
    """No shell type should produce a payload containing '4444' as a literal port.
    The default port is 443; operators must explicitly override and acknowledge
    non-stealth ports at the CLI layer."""
    gen = ReverseShellGenerator(tmp_kb_db)
    for shell_type in ("python", "powershell", "bash", "perl", "ruby"):
        result = gen.generate("10.0.0.1", 443, shell_type)
        raw = result.raw_command or ""
        obfuscated = result.obfuscated_command or ""
        assert not PORT_BANNED.search(raw + obfuscated), (
            f"Banned port '4444' found in {shell_type} shell output."
        )


def test_bash_shell_no_dev_tcp(tmp_kb_db):
    """`/dev/tcp` is detected by shell-based EDR hooks. The bash template must
    use an alternative (e.g., Python fallback, socat) or encode the path."""
    gen = ReverseShellGenerator(tmp_kb_db)
    result = gen.generate("10.0.0.1", 443, "bash")
    assert not BASH_BANNED.search(result.raw_command or ""), (

    gen = ReverseShellGenerator(tmp_kb_db)

    assert not NC_EXEC_BANNED.search(result.raw_command or ""), (

def test_beacon_no_raw_wget_curl(tmp_kb_db):
    """Beacons must not use raw wget/curl invocations. All outbound HTTP must go
    through the curl_cffi wrapper or the compiled C stub to avoid process-tree signatures."""
    gen = C2Generator(tmp_kb_db)
    result = gen.generate("powershell", "https", ["https://cdn.example.com/update"])
    beacon_src = result.beacon_source or ""
    assert not WGET_CURL_BANNED.search(beacon_src), (
        "Banned wget/curl invocation found in beacon source."
    )


def test_beacon_no_hardcoded_rfc1918_c2(tmp_kb_db):
    """Beacon templates must use Jinja2 placeholders for C2 addresses.
    RFC 1918 addresses must never be hardcoded into the template output."""
    gen = C2Generator(tmp_kb_db)

    beacon_src = result.beacon_source or ""

        "Hardcoded RFC 1918 C2 address found in beacon source. Use Jinja2 placeholder."
    )


def test_gaussian_sleep_distribution():
    """Validate that the jitter implementation uses a Gaussian (not uniform) distribution.
    A uniform distribution has near-zero skew and low kurtosis; Gaussian has measurable stdev."""
    samples = [gaussian_sleep(60, 20) for _ in range(1000)]
    assert abs(statistics.mean(samples) - 60) < 5, "Gaussian mean must be close to base interval."
    assert statistics.stdev(samples) > 5,           "Gaussian stdev must be non-trivial."
    assert all(30 <= s <= 90 for s in samples),     "All samples must stay within 50%–150% bounds."
```

## 16. ANTI-PATTERNS CATALOGUE (v7.1 — COMPLETE)

| Anti-Pattern | Why Banned | Correct Alternative |
|--------------|-----------|---------------------|
| Skipping `scope_gate.assert_in_scope()` in Phase 2 or Phase 5 code | Silent out-of-scope execution | First line of every remote operation |
| Using port 4444 as default listener port | Immediately flagged by IDS/EDR | Default to 443; document override requirement |
| Uniform jitter in beacon timing | Statistical analysis detects regular distribution | Gaussian jitter via `random.gauss()` |
| Hardcoded User-Agent strings in beacon templates | Baseline comparison detects static UA | Dynamic UA from Phase 1 host OS fingerprint |
| Creating new directories in `/tmp/<random>/` for staging | FIM alerts on new temp directory creation | Stage in existing writable system subdirectories |
| `time.sleep()` in beacon loop | Blocks event loop | `asyncio.sleep()` or `threading.Event.wait()` |
| Hardcoded C2 addresses in agent templates | Static signatures enable detection | Jinja2 `{{ c2_urls }}` placeholder |
| NTLM auth for lateral movement when Kerberos is available | NTLM alert; detectable in network logs | Kerberos PTT (`--ticket <ccache>`) |
| `svcctl` named pipe for SMB exec | Well-known signature; alerted by Sysmon Event ID 18 | Use `atsvc` or `winreg` pipes |
| Spawning new processes for reverse shell | Parent–child tree anomaly detection | Process injection mode (`--inject-pid`) |
| Bulk file reads in rapid succession | EDR file activity telemetry | Stagger reads: `DEFAULT_STAGGER = 2.0 s`; 30 s pause per 100 files |
| Exfiltration outside business hours | SIEM temporal anomaly correlation | `--window 09:00-17:00`; respect same window as lateral movement |
| Writing persistence artifacts with current timestamp | FIM baseline deviation | Timestamp mirroring: `os.utime(target, (ref.st_atime, ref.st_mtime))` |
| `\Run` registry key persistence | Autoruns trivially detects it; heavily alerted | COM object hijacking (`com_hijack`) for lower detection surface |
| Logging exfiltrated file contents to DB or audit log | Sensitive data in engagement DB | Log metadata only: path, hash, size |
| `process.communicate()` in lateral movement | OOM on large outputs | Stream with timeout; truncate to 64 KB |
| Executing lateral movement without `questionary.confirm()` | Bypasses human-in-the-loop | Prompt is mandatory |
| Using `requests` library in FORGE core | Distinctive TLS fingerprint | `curl_cffi` for all FORGE outbound HTTP |
| Storing AES keys in `agents` table as plaintext | DB compromise exposes session keys | Store as placeholder; inject at deploy time |
| `del password` omitted after auth adapter call | Password lingers in memory | Explicit `del password` immediately after adapter call |
| `@validator` (Pydantic v1) | Deprecated in v2 | `@field_validator` with `@classmethod` |
| f-string injection of raw user data into Jinja2 | Template injection | Always use `tmpl.render(var=value)` |
| Passing untyped `dict` as `cred` to `lateral_movement.execute()` | No type safety; ccache_path / auth_type semantics undefined | Use `LateralMovementCredential` Pydantic model (§4.4) |
| Invoking external tools without version assertion | Silent degradation on mismatched tool versions | Call `assert_tool_version()` at module init; raise `ToolVersionError` (§13.3) |
| Evasion tests omitted from Phase 5 modules | No CI signal when banned patterns leak into output | ≥ 1 evasion assertion test per module in `test_evasion_assertions.py` (§1.4, §15.2) |
| Using operator's personal GitHub account for Module 2-J or 2-I searches | Operator identity correlated with target via GitHub query logs | Dedicated throwaway GitHub account; PAT registered to burn account only |
| Making Module 2-J validator API calls without `--validation-proxy` | Operator IP logged by AWS/Stripe/GitHub as origin of key probe | Enforce proxy requirement; CLI exits code `1` if absent and `--no-validate` not set |
| Hardcoding a POST body with real field names for Supabase write test (Module 4-G) | Creates a traceable record in target DB | Use a recognisable test payload string (e.g., `__forge_probe__`); document cleanup step |
| Crawling beyond `--depth` limit or off-domain in IDOR scanner (Module 4-D) | Accidental out-of-scope requests | Scope gate enforced at every URL fetch, not just the crawl entry point |
| Invoking Module 4-E without capturing and deleting Agneyastra JSON output file | Sensitive target data persists on operator disk | Register output file with `cleanup.py` before subprocess call; delete on completion and `forge clean` |
| Storing Firebase API keys extracted by Module 4-F in plaintext in `cloud_assets` | DB compromise exposes target service credential | Age-encrypt API keys at insert time |

| **COM Hijack** | Persistence technique: write payload path to `HKCU\Software\Classes\CLSID\<guid>\InprocServer32` for a CLSID regularly queried by a legitimate application; no `Run` key modification required. |
| **Collector Stagger** | Deliberate delay between individual file reads in Module 5-H to avoid bulk-read EDR telemetry. |
| **Auth Adapter** | `BaseAuthAdapter` subclass (Module 2-B) implementing a specific protocol. Fully async; returns `(bool, Optional[str])`. |
| **AES-256-GCM** | Authenticated encryption for all C2 traffic and exfiltrated data. Keys are operator-supplied at deploy time. |
| **FTS5** | SQLite Full-Text Search extension v5. Used for fast LOLBin and exploit description search. |
