## 11.17 Text Cleaning Pipeline (`--clean-text`)

### 11.17.1 Motivation & Design Rationale

Phase 2 OSINT modules — in particular Module 2-E (social media scraping) and web content
scrapers — produce raw text that is frequently polluted with:

- **Emoji and non-BMP Unicode** — break tokenisation in Qwen2.5's SentencePiece vocabulary and
  cause silent token-budget overflows when character counts diverge from token counts.
- **Obfuscated text** — leet-speak (`p@ssw0rd`), base64-encoded strings, and ROT-13 fragments
  that appear in paste site content and forum dumps; left uncleaned, the LLM will reproduce
  obfuscated strings verbatim rather than interpreting their semantic content.
- **Zero-width and control characters** — frequently injected into social profile bios and paste
  site posts as an anti-scraping measure; invisible to the human reviewer but present in the
  LLM context, consuming tokens and occasionally disrupting generation.
- **Inconsistent Unicode normalisation** — mixing NFC and NFD forms produces non-identical
  strings from equivalent text, which breaks deduplication in the `ContextBuilder`.

The cleaning pipeline runs **before the prompt assembler** (`PromptAssembler`) as a pre-processing
step on any text field destined for the LLM context. It is **opt-in via `--clean-text`** to
preserve determinism: operators who have already normalised their input, or who need to inspect
raw artefacts, should not have cleaning applied silently.

The pipeline is implemented locally, using Python's standard library plus `unicodedata` and
`ftfy` (a pure-Python Unicode fixer). It does **not** make network requests to texttools.org or
CyberChef's web interface at runtime. The operational logic of both tools is replicated
offline:

| External Tool | What We Replicate Locally | Library Used |
|---|---|---|
| `texttools.org/remove-emojis` | Emoji and non-BMP character removal via Unicode category filtering | `unicodedata` (stdlib) |
| CyberChef `Magic` operation | Encoding detection and decoding (base64, hex, ROT-13, URL-encode) | `ftfy`, custom decoder chain |
| CyberChef `Normalise Unicode` | NFC normalisation | `unicodedata.normalize` (stdlib) |
| CyberChef `Strip non-printable` | Control character removal | `unicodedata` category check |

> **OPSEC note:** Never invoke texttools.org or CyberChef's hosted API during an engagement.
> Both tools log submitted data server-side. The local implementation is functionally equivalent
> and carries zero external exposure.

---

### 11.17.2 Cleaning Operations Matrix

Operations are applied in a fixed order. Each can be individually toggled via `CleaningConfig`.
The default profile (`CleaningConfig.default()`) enables all operations except
`decode_obfuscation`, which is disabled by default due to false-positive risk on
legitimate technical strings (hex digests, encoded payloads).

| Step | Operation | Default | Risk of False Positive | Notes |
|------|-----------|---------|----------------------|-------|
| 1 | Unicode NFC normalisation | ✅ Enabled | None | Idempotent; safe to always apply |
| 2 | `ftfy` mojibake repair | ✅ Enabled | Very low | Fixes mis-decoded UTF-8 / Latin-1 sequences |
| 3 | Control character removal (U+0000–U+001F, U+007F–U+009F) | ✅ Enabled | None | Preserves `\n`, `\t` |
| 4 | Zero-width character removal (U+200B, U+200C, U+FEFF, etc.) | ✅ Enabled | None | Invisible; no semantic content |
| 5 | Emoji removal (Unicode category `So`, `Sm`, non-BMP code points) | ✅ Enabled | Low | Preserves mathematical symbols; strips pictographs |
| 6 | ROT-13 decoding (heuristic: >50% ASCII letters, triggers on common patterns) | ✅ Enabled | Medium | Applied only if heuristic confidence > 0.8 |
| 7 | Base64 decoding (heuristic: regex match + valid UTF-8 decode) | ⚠️ Optional | Medium-High | Off by default under `decode_obfuscation=False` |
| 8 | Hex string decoding (heuristic: even-length `[0-9a-fA-F]+` > 16 chars) | ⚠️ Optional | Medium | Off by default |
| 9 | URL-percent decoding | ✅ Enabled | Low | `urllib.parse.unquote` |
| 10 | Whitespace normalisation (collapse runs, strip trailing) | ✅ Enabled | None | Applied last |

### 11.17.3 Implementation (`forge/phase6/cleaner.py`)

```python
# forge/phase6/cleaner.py
from __future__ import annotations

import base64
import codecs
import logging
import re
import unicodedata
from dataclasses import dataclass, field
from urllib.parse import unquote

logger = logging.getLogger(__name__)

# ---------------------------------------------------------------------------
# Zero-width and invisible Unicode characters
# ---------------------------------------------------------------------------
_ZERO_WIDTH = re.compile(
    r"[\u200b\u200c\u200d\u200e\u200f\u202a-\u202e\u2060\u2061\ufeff\u00ad]"
)

# Control characters: C0 (U+0000–U+001F) and C1 (U+0080–U+009F), minus tab and newline
_CONTROL_CHARS = re.compile(r"[\x00-\x08\x0b\x0c\x0e-\x1f\x7f-\x9f]")

# Non-BMP code points (outside Basic Multilingual Plane) — catches most emoji
_NON_BMP = re.compile(r"[\U00010000-\U0010ffff]")

# Base64 heuristic: minimum 16 chars of valid base64 alphabet, padded
_BASE64_PATTERN = re.compile(r"\b([A-Za-z0-9+/]{16,}={0,2})\b")

# Hex string heuristic: even-length sequences ≥ 16 hex chars
_HEX_PATTERN = re.compile(r"\b([0-9a-fA-F]{16,})\b")

# URL percent-encoding detection
_URL_ENCODED = re.compile(r"%[0-9a-fA-F]{2}")


# ---------------------------------------------------------------------------
# Configuration
# ---------------------------------------------------------------------------

@dataclass
class CleaningConfig:
    """
    Fine-grained control over which cleaning operations are applied.
    """
    normalise_unicode: bool = True
    fix_mojibake: bool = True
    strip_control_chars: bool = True
    strip_zero_width: bool = True
    strip_emoji: bool = True
    decode_rot13: bool = True
    decode_obfuscation: bool = False  # base64 + hex; off by default (high FP risk)
    decode_url_encoding: bool = True
    normalise_whitespace: bool = True

    @classmethod
    def default(cls) -> "CleaningConfig":
        """Conservative default: safe operations only."""
        return cls()

    @classmethod
    def aggressive(cls) -> "CleaningConfig":
        """All operations enabled, including obfuscation decoding."""
        return cls(decode_obfuscation=True)


# ---------------------------------------------------------------------------
# Result
# ---------------------------------------------------------------------------

@dataclass
class CleaningResult:
    original_text: str
    cleaned_text: str
    operations_applied: list[str] = field(default_factory=list)
    chars_removed: int = 0
    decodings_applied: list[str] = field(default_factory=list)  # audit trail

    @property
    def was_modified(self) -> bool:
        return self.original_text != self.cleaned_text


# ---------------------------------------------------------------------------
# Individual cleaners
# ---------------------------------------------------------------------------

def _is_emoji(char: str) -> bool:
    """
    Return True if char is an emoji or pictographic symbol.
    Uses Unicode categories: So (Other Symbol), Sm (Math Symbol),
    and the non-BMP check for code points > U+FFFF.
    """
    cp = ord(char)
    if cp > 0xFFFF:
        return True
    cat = unicodedata.category(char)
    if cat in ("So",):
        return True
    # Emoji presentation range (approximate; sufficient for OSINT text)
    if 0x2600 <= cp <= 0x27BF:
        return True
    if 0xFE00 <= cp <= 0xFE0F:  # variation selectors
        return True
    return False


def _strip_emoji(text: str) -> tuple[str, int]:
    cleaned = "".join(ch for ch in text if not _is_emoji(ch))
    removed = len(text) - len(cleaned)
    return cleaned, removed


def _rot13_confidence(text: str) -> float:
    """
    Estimate likelihood that text is ROT-13 encoded.
    Heuristic: high proportion of ASCII letters AND matches common ROT-13
    artefacts (e.g. 'gur', 'vf', 'naq' — ROT-13 of 'the', 'is', 'and').
    Returns 0.0–1.0.
    """
    if not text:
        return 0.0
    letters = sum(1 for c in text if c.isalpha())
    alpha_ratio = letters / len(text)
    if alpha_ratio < 0.5:
        return 0.0
    decoded = codecs.decode(text, "rot_13")
    # Check for common English words in the decoded version
    common_words = {"the", "and", "is", "of", "to", "a", "in", "that", "it"}
    decoded_words = set(decoded.lower().split())
    word_hits = len(common_words & decoded_words)
    confidence = min(1.0, (alpha_ratio * 0.4) + (word_hits * 0.12))
    return confidence


def _try_base64_decode(match: re.Match) -> str:
    """
    Attempt to decode a base64 candidate. Returns decoded UTF-8 string
    if successful and the result is printable ASCII; otherwise returns original.
    """
    candidate = match.group(1)
    try:
        decoded = base64.b64decode(candidate + "==").decode("utf-8")
        # Accept only if result is >50% printable ASCII
        printable = sum(1 for c in decoded if 0x20 <= ord(c) <= 0x7E)
        if printable / max(len(decoded), 1) > 0.5:
            return f"[decoded-b64: {decoded}]"
    except Exception:
        pass
    return candidate


def _try_hex_decode(match: re.Match) -> str:
    """
    Attempt to decode a hex string as UTF-8. Returns decoded string
    in annotation form if successful; otherwise returns original.
    """
    candidate = match.group(1)
    if len(candidate) % 2 != 0:
        return candidate
    try:
        decoded = bytes.fromhex(candidate).decode("utf-8")
        printable = sum(1 for c in decoded if 0x20 <= ord(c) <= 0x7E)
        if printable / max(len(decoded), 1) > 0.5:
            return f"[decoded-hex: {decoded}]"
    except Exception:
        pass
    return candidate


# ---------------------------------------------------------------------------
# Main pipeline
# ---------------------------------------------------------------------------

def clean_text(text: str, config: CleaningConfig | None = None) -> CleaningResult:
    """
    Apply the configured cleaning pipeline to a text string.

    Designed for use on OSINT-sourced text (social media bios, paste site content,
    scraped web text) before injection into the LLM prompt context.

    Args:
        text:   Raw input text.
        config: Cleaning configuration. Defaults to CleaningConfig.default().

    Returns:
        CleaningResult with cleaned text and an audit trail of applied operations.
    """
    cfg = config or CleaningConfig.default()
    original = text
    ops: list[str] = []
    decodings: list[str] = []
    chars_removed = 0

    # Step 1: Unicode NFC normalisation
    if cfg.normalise_unicode:
        normalised = unicodedata.normalize("NFC", text)
        if normalised != text:
            ops.append("unicode-nfc-normalise")
        text = normalised

    # Step 2: ftfy mojibake repair
    if cfg.fix_mojibake:
        try:
            import ftfy
            fixed = ftfy.fix_text(text)
            if fixed != text:
                ops.append("ftfy-mojibake-repair")
            text = fixed
        except ImportError:
            logger.debug("ftfy not installed; skipping mojibake repair. pip install ftfy.")

    # Step 3: Control character removal
    if cfg.strip_control_chars:
        cleaned = _CONTROL_CHARS.sub("", text)
        removed = len(text) - len(cleaned)
        if removed > 0:
            ops.append(f"strip-control-chars ({removed} removed)")
            chars_removed += removed
        text = cleaned

    # Step 4: Zero-width character removal
    if cfg.strip_zero_width:
        cleaned = _ZERO_WIDTH.sub("", text)
        removed = len(text) - len(cleaned)
        if removed > 0:
            ops.append(f"strip-zero-width ({removed} removed)")
            chars_removed += removed
        text = cleaned

    # Step 5: Emoji removal
    if cfg.strip_emoji:
        cleaned, removed = _strip_emoji(text)
        if removed > 0:
            ops.append(f"strip-emoji ({removed} removed)")
            chars_removed += removed
        text = cleaned

    # Step 6: ROT-13 decoding (heuristic)
    if cfg.decode_rot13:
        confidence = _rot13_confidence(text)
        if confidence > 0.8:
            decoded = codecs.decode(text, "rot_13")
            ops.append(f"decode-rot13 (confidence={confidence:.2f})")
            decodings.append(f"rot13: confidence={confidence:.2f}")
            text = decoded

    # Step 7 & 8: Base64 / Hex decoding (optional; off by default)
    if cfg.decode_obfuscation:
        b64_result = _BASE64_PATTERN.sub(_try_base64_decode, text)
        if b64_result != text:
            ops.append("decode-base64 (partial)")
            decodings.append("base64-partial")
            text = b64_result

        hex_result = _HEX_PATTERN.sub(_try_hex_decode, text)
        if hex_result != text:
            ops.append("decode-hex (partial)")
            decodings.append("hex-partial")
            text = hex_result

    # Step 9: URL percent-decoding
    if cfg.decode_url_encoding and _URL_ENCODED.search(text):
        decoded = unquote(text)
        if decoded != text:
            ops.append("decode-url-percent-encoding")
            decodings.append("url-percent")
        text = decoded

    # Step 10: Whitespace normalisation (last)
    if cfg.normalise_whitespace:
        normalised = re.sub(r"[ \t]+", " ", text)          # collapse horizontal whitespace
        normalised = re.sub(r"\n{3,}", "\n\n", normalised)  # max 2 consecutive newlines
        normalised = normalised.strip()
        if normalised != text:
            ops.append("normalise-whitespace")
        text = normalised

    return CleaningResult(
        original_text=original,
        cleaned_text=text,
        operations_applied=ops,
        chars_removed=chars_removed,
        decodings_applied=decodings,
    )


def clean_context_fields(ctx_dict: dict, config: CleaningConfig | None = None) -> dict:
    """
    Recursively walk a dict (e.g. ReportContext.model_dump()) and apply
    clean_text() to all string leaf values.

    Used by ContextBuilder when --clean-text is active to sanitise all
    OSINT text fields before they reach the PromptAssembler.

    Args:
        ctx_dict: A dict (possibly nested) containing string fields.
        config:   Cleaning config. Defaults to CleaningConfig.default().

    Returns:
        New dict with all string values cleaned. Non-string values are unchanged.
    """
    result = {}
    for key, value in ctx_dict.items():
        if isinstance(value, str):
            result[key] = clean_text(value, config).cleaned_text
        elif isinstance(value, dict):
            result[key] = clean_context_fields(value, config)
        elif isinstance(value, list):
            result[key] = [
                clean_context_fields(item, config) if isinstance(item, dict)
                else (clean_text(item, config).cleaned_text if isinstance(item, str) else item)
                for item in value
            ]
        else:
            result[key] = value
    return result
```

### 11.17.4 Integration Points

The cleaning pipeline integrates at **two distinct points** in the Phase 6 pipeline:

#### Point A: Context-Level Cleaning (Recommended)

Applied by `build_report_context()` before the context is passed to `assemble_prompt()`.
When `--clean-text` is set, the returned `ReportContext` dict is passed through
`clean_context_fields()` before JSON serialisation:

```python
# forge/phase6/context_builder.py  (integration fragment)

from forge.phase6.cleaner import clean_context_fields, CleaningConfig

def build_report_context(
    engagement_id: int,
    db_path: Path,
    clean_text: bool = False,
    cleaning_config: CleaningConfig | None = None,
) -> ReportContext:
    # ... existing query logic ...

    ctx = ReportContext(...)
    ctx.overall_risk = _derive_overall_risk(ctx)

    if clean_text:
        cleaned_dict = clean_context_fields(
            ctx.model_dump(),
            config=cleaning_config or CleaningConfig.default(),
        )
        ctx = ReportContext.model_validate(cleaned_dict)
        logger.info(
            "Text cleaning applied to context. "
            "Use --no-clean-text to disable."
        )

    return ctx
```

#### Point B: Field-Level Cleaning (Selective)

For high-noise fields specifically — `social_profiles[*].display_names`,
`email_intelligence[*].platforms`, raw paste content — the operator can invoke
`clean_text()` directly on individual strings. This is the preferred approach
when only a subset of context data originates from OSINT scraping.

```python
from forge.phase6.cleaner import clean_text, CleaningConfig

# Example: cleaning a single raw paste excerpt before inclusion
raw_paste = "chEck 0ut 🔥 p@$$w0rd: c29tZXRoaW5n"  # emoji + possible base64
result = clean_text(raw_paste, CleaningConfig.aggressive())
print(result.cleaned_text)
# Output: "chEck 0ut p@$$w0rd: [decoded-b64: something]"
print(result.operations_applied)
# Output: ['unicode-nfc-normalise', 'strip-emoji (1 removed)', 'decode-base64 (partial)', 'normalise-whitespace']
```

### 11.17.5 Cleaning Audit Trail

Every cleaning operation is recorded in the `CleaningResult.operations_applied` list and
written to the engagement audit log. This ensures reproducibility: an operator reviewing
a delivered report can determine precisely what transformations were applied to any given
piece of OSINT data before it reached the LLM.

```python
# forge/phase6/context_builder.py  (audit logging fragment)

import json
from forge.db import write_audit_log

def _log_cleaning_summary(engagement_id: int, results: list[CleaningResult]) -> None:
    modified = [r for r in results if r.was_modified]
    summary = {
        "total_fields_cleaned": len(results),
        "fields_modified": len(modified),
        "total_chars_removed": sum(r.chars_removed for r in results),
        "decodings_applied": [d for r in results for d in r.decodings_applied],
    }
    write_audit_log(
        engagement_id=engagement_id,
        event="phase6_text_cleaning",
        detail=json.dumps(summary),
    )
```

The audit record is stored in the `audit_log` table (defined in Chunk 0) with
`event='phase6_text_cleaning'` and a JSON summary of what was changed.

### 11.17.6 CLI Integration

The `--clean-text` flag is added to the `forge report generate` command:

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--clean-text` | `flag` | Off | Enable text cleaning pipeline on all OSINT context fields before LLM injection |
| `--clean-aggressive` | `flag` | Off | Enable base64/hex decoding in addition to standard cleaning. Implies `--clean-text`. High false-positive risk; review output carefully. |

```
forge report generate --engagement 4 \
    --clean-text \
    --format pdf \
    --output-dir ./reports/
```

```
forge report generate --engagement 4 \
    --clean-aggressive \
    --format html
```

> **Operator guidance:** `--clean-aggressive` should be reserved for engagements where
> paste site data or forum scrapes are a significant source of OSINT findings.
> Always review the audit log entry for `phase6_text_cleaning` before delivering
> a report generated with this flag to confirm no legitimate technical strings
> (e.g. CVSS vectors, CVE descriptions containing hex offsets) were decoded.

### 11.17.7 Unit Tests

```python
# tests/phase6/test_cleaner.py
import pytest
from forge.phase6.cleaner import clean_text, CleaningConfig, clean_context_fields


def test_emoji_removal():
    result = clean_text("Hello 🔥 World 💀", CleaningConfig.default())
    assert "🔥" not in result.cleaned_text
    assert "💀" not in result.cleaned_text
    assert "Hello" in result.cleaned_text
    assert result.chars_removed > 0
    assert any("strip-emoji" in op for op in result.operations_applied)


def test_zero_width_removal():
    # Zero-width space (U+200B) injected mid-word
    text = "pass\u200bword"
    result = clean_text(text)
    assert "\u200b" not in result.cleaned_text
    assert result.cleaned_text == "password"


def test_control_char_removal():
    text = "clean\x01text\x07here"
    result = clean_text(text)
    assert "\x01" not in result.cleaned_text
    assert "\x07" not in result.cleaned_text
    assert "cleantexthere" in result.cleaned_text


def test_url_decoding():
    text = "user%40example.com%20is%20compromised"
    result = clean_text(text)
    assert "user@example.com is compromised" in result.cleaned_text
    assert any("url" in op for op in result.operations_applied)


def test_base64_decode_aggressive():
    # "something" base64-encoded
    text = "value: c29tZXRoaW5n"
    result = clean_text(text, CleaningConfig.aggressive())
    assert "decoded-b64: something" in result.cleaned_text


def test_base64_not_decoded_in_default():
    # Default config should NOT decode base64
    text = "hash: c29tZXRoaW5n"
    result = clean_text(text, CleaningConfig.default())
    assert "decoded-b64" not in result.cleaned_text


def test_clean_context_fields_recursive():
    ctx = {
        "engagement_name": "Test 🔥 Engagement",
        "osint": {
            "email_intelligence": [
                {"email": "user\u200b@example.com", "platforms": ["LinkedIn"]}
            ]
        }
    }
    cleaned = clean_context_fields(ctx)
    assert "🔥" not in cleaned["engagement_name"]
    assert "\u200b" not in cleaned["osint"]["email_intelligence"][0]["email"]


def test_whitespace_normalisation():
    text = "word1   word2\n\n\n\nword3"
    result = clean_text(text)
    assert "   " not in result.cleaned_text      # collapsed spaces
    assert "\n\n\n" not in result.cleaned_text   # collapsed newlines


def test_noop_on_clean_text():
    text = "A clean, normal ASCII string with no issues."
    result = clean_text(text)
    assert result.cleaned_text == text
    assert not result.was_modified
```

### 11.17.8 Anti-Patterns & Edge Cases

**Anti-pattern:** Applying `CleaningConfig.aggressive()` globally across all context fields.

The hex decoder will incorrectly annotate CVE identifiers and CVSS scores
(e.g. `CVSS:3.1/AV:N/AC:L` contains characters that partially match the hex heuristic).
Apply aggressive cleaning **only to OSINT text fields** (`social_profiles`, `username_hits`,
paste content), never to structured data fields like `exploit_suggestions` or CVE descriptions.

**Edge case:** Multi-byte emoji composed via ZWJ sequences (e.g. 👩‍💻 = U+1F469 + U+200D + U+1F4BB).
The `_is_emoji()` function removes the visible emoji code points, but the ZWJ (U+200D) may
remain. The `strip_zero_width` step (Step 4) runs before emoji removal (Step 5) and handles
this correctly — ZWJ is removed in Step 4, leaving the component emoji code points for
Step 5 to strip.

**Edge case:** Legitimate base64 data in OSINT context — public SSH keys, PGP fingerprints.
These will be annotated as `[decoded-b64: ...]` under `--clean-aggressive`. The validator
does not currently flag this; however, the `CleaningResult.decodings_applied` audit record
will capture every such substitution. Operators should review this list before delivery.

## 11.18 Ongoing Intelligence Integration (LeakLooker)

### 11.18.1 Motivation & Design Rationale

Phase 2-F optionally configures monitoring alerts against paste sites and breach aggregators
via LeakLooker. These alerts surface **new intelligence that arrives after the engagement's
active testing window** — post-engagement credential exposures, new paste site dumps referencing
target domains, and fresh breach notifications.

Including this intelligence in the final report provides concrete, time-bounded evidence of
ongoing exposure, which is particularly compelling in executive-level reporting ("the organisation
remains exposed as of the report date") and in retest scheduling conversations.

**Design decisions:**

1. **The `Ongoing Intelligence` section is conditionally rendered.** If no monitoring was
   configured in Phase 2-F, or if no new findings have arrived since the last report, the
   section is omitted. The validator does not require it as a mandatory section (it does not
   appear in the `MANDATORY_SECTIONS` list). This avoids a confusing empty section.

2. **LeakLooker findings are stored in the engagement DB at ingest time** (via `forge monitor poll`),
   not fetched live during report generation. Phase 6 remains network-free at runtime.

3. **The section headline is time-stamped**: the report explicitly states the date range of
   monitored findings to avoid ambiguity about data freshness.

4. **Sensitive finding details are redacted by default.** Paste URLs are hashed; plaintext
   credential excerpts from pastes are replaced with metadata-only summaries. Full excerpts
   are available in the Appendix only if `--appendix` is set.

### 11.18.3 ContextBuilder Extension

```python
# forge/phase6/context_builder.py  (ongoing intelligence fragment)

from datetime import datetime, timezone
from forge.phase6.models import OngoingIntelligenceContext, PasteFinding


def _build_ongoing_intelligence_context(
    engagement_id: int,
    con: sqlite3.Connection,
    last_reported_at: datetime | None,
) -> OngoingIntelligenceContext:
    """
    Aggregate LeakLooker monitoring findings into a structured context block.
    Only called if monitoring was enabled for the engagement.

    Args:
        engagement_id:   Engagement DB ID.
        con:             Open SQLite connection with row_factory set.
        last_reported_at: Timestamp of the previous report generation. If None,
                          returns all findings since Phase 2-F setup.

    Returns:
        OngoingIntelligenceContext populated from the monitoring_findings table.
    """
    # Check if monitoring was configured
    monitoring_row = con.execute(
        "SELECT enabled, started_at, keywords_json FROM monitoring_config WHERE engagement_id=?",
        (engagement_id,),
    ).fetchone()

    if not monitoring_row or not monitoring_row["enabled"]:
        return OngoingIntelligenceContext(monitoring_enabled=False)

    keywords = json.loads(monitoring_row["keywords_json"] or "[]")
    window_start = last_reported_at or datetime.fromisoformat(monitoring_row["started_at"])
    window_end = datetime.now(tz=timezone.utc)

    # Fetch new findings since last_reported_at
    findings_rows = con.execute(
        """
        SELECT paste_id_hash, source_platform, discovered_at, keyword_matched,
               credential_count, plaintext_count, excerpt_available, severity
        FROM monitoring_findings
        WHERE engagement_id = ?
          AND discovered_at > ?
        ORDER BY discovered_at DESC
        """,
        (engagement_id, window_start.isoformat()),
    ).fetchall()

    new_breach_sources = [
        r["source_name"] for r in con.execute(
            """
            SELECT DISTINCT source_name FROM monitoring_findings
            WHERE engagement_id=?
              AND discovered_at > ?
              AND source_platform NOT IN (
                  SELECT DISTINCT source_name FROM credentials WHERE engagement_id=?
              )
            """,
            (engagement_id, window_start.isoformat(), engagement_id),
        ).fetchall()
    ]

    paste_findings = [
        PasteFinding(
            paste_id_hash=r["paste_id_hash"],
            source_platform=r["source_platform"],
            discovered_at=datetime.fromisoformat(r["discovered_at"]),
            keyword_matched=r["keyword_matched"],
            credential_count=r["credential_count"] or 0,
            plaintext_count=r["plaintext_count"] or 0,
            excerpt_available=bool(r["excerpt_available"]),
            severity=r["severity"] or "low",
        )
        for r in findings_rows
    ]

    high_severity = sum(1 for f in paste_findings if f.severity == "high")

    # Pre-generate a narrative summary for prompt injection
    # (avoids injecting raw PasteFinding objects into the template)
    summary = _generate_monitoring_narrative(paste_findings, window_start, window_end)

    return OngoingIntelligenceContext(
        monitoring_enabled=True,
        monitored_keywords=keywords,
        monitoring_window_start=window_start,
        monitoring_window_end=window_end,
        new_findings_count=len(paste_findings),
        high_severity_count=high_severity,
        paste_findings=paste_findings,
        new_breach_sources=new_breach_sources,
        summary_narrative=summary,
    )


def _generate_monitoring_narrative(
    findings: list[PasteFinding],
    window_start: datetime,
    window_end: datetime,
) -> str:
    """
    Produce a one-paragraph narrative summary of monitoring findings
    for injection into the LLM prompt. Deliberately concise; the LLM
    expands this into the full Ongoing Intelligence section.
    """
    if not findings:
        return (
            f"No new monitoring findings were identified between "
            f"{window_start.date()} and {window_end.date()}."
        )

    total = len(findings)
    high = sum(1 for f in findings if f.severity == "high")
    platforms = list({f.source_platform for f in findings})
    cred_total = sum(f.credential_count for f in findings)
    plaintext_total = sum(f.plaintext_count for f in findings)

    return (
        f"Between {window_start.date()} and {window_end.date()}, "
        f"{total} new paste/breach findings were identified across "
        f"{', '.join(platforms)}. "
        f"Of these, {high} are classified as high severity. "
        f"An estimated {cred_total} credentials were exposed "
        f"({plaintext_total} in plaintext). "
        f"Full paste metadata is available in the Appendix."
    )
```

> **Note on `_generate_monitoring_narrative`:** The narrative is injected as a pre-computed
> summary string, not as a raw JSON object. This constrains the LLM's task in the Ongoing
> Intelligence section to expansion and contextualisation, rather than raw data formatting —
> which a 1.5B model handles poorly under token pressure.

### 11.18.6 Validator Rule Update (V-10)

A new validation rule is added to enforce consistency between the Ongoing Intelligence section
and the Executive Summary when monitoring findings are present.

| Rule ID | Description | Severity | Action on Failure |
|---------|-------------|----------|-------------------|
| V-10 | Ongoing Intelligence section present but Executive Summary contains no reference to monitoring findings | MEDIUM | Log warning; in `--strict` mode, raise `ValidationError` |

```python
# forge/phase6/validator.py  (V-10 addition)

def _check_v10_exec_summary_monitoring_reference(
    text: str,
    ongoing_intel: "OngoingIntelligenceContext",
    strict: bool,
    result: ValidationResult,
) -> None:
    """
    V-10: If monitoring findings are present and Section 8 was rendered,
    verify the Executive Summary acknowledges the monitoring window.
    """
    if not ongoing_intel.monitoring_enabled or ongoing_intel.new_findings_count == 0:
        return

    exec_match = re.search(
        r"## 1\. Executive Summary\n(.*?)(?=\n## )", text, re.DOTALL
    )
    if not exec_match:
        return  # V-06 already handles missing section

    exec_text = exec_match.group(1).lower()
    monitoring_keywords = {"monitoring", "ongoing", "intelligence", "paste", "post-engagement"}
    has_reference = any(kw in exec_text for kw in monitoring_keywords)

    if not has_reference:
        msg = (
            "[V-10] Ongoing Intelligence section is present but the Executive Summary "
            "contains no reference to monitoring findings. Update the Executive Summary "
            "to acknowledge post-engagement exposure."
        )
        if strict:
            result.errors.append(msg)
        else:
            result.warnings.append(msg)
            logger.warning(msg)
```

) -> ValidationResult:

### 11.18.7 LeakLooker Ingestion Module (`forge/phase2/leaklooker_ingest.py`)

Phase 6 is read-only; it consumes monitoring findings that were previously ingested and stored
in the engagement DB. The ingestor runs as a separate command (`forge monitor poll`) during or
after the engagement's active window.

```python
# forge/phase2/leaklooker_ingest.py
from __future__ import annotations

import hashlib
import json
import logging
import sqlite3
from datetime import datetime, timezone
from pathlib import Path

import httpx

logger = logging.getLogger(__name__)

LEAKLOOKER_BASE = "https://leaklooker.io/api/v1"


def _hash_url(url: str) -> str:
    """One-way hash of a paste URL. Prevents raw URLs appearing in the DB."""
    return hashlib.sha256(url.encode()).hexdigest()[:32]


def _classify_severity(credential_count: int, plaintext_count: int) -> str:
    if plaintext_count > 0:
        return "high"
    if credential_count > 5:
        return "medium"
    return "low"


def poll_leaklooker(
    engagement_id: int,
    db_path: Path,
    api_key: str,
    since: datetime | None = None,
) -> int:
    """
    Poll LeakLooker for new findings and persist them to the monitoring_findings table.

    Args:
        engagement_id: Engagement DB ID.
        db_path:       Path to the SQLite engagement DB.
        api_key:       LeakLooker API key (stored in operator keychain, not in DB).
        since:         Only return findings newer than this timestamp. Defaults to
                       the monitoring_config.started_at value for the engagement.

    Returns:
        Number of new findings inserted.
    """
    con = sqlite3.connect(db_path)
    con.row_factory = sqlite3.Row

    # Fetch monitoring keywords
    config_row = con.execute(
        "SELECT keywords_json, started_at FROM monitoring_config WHERE engagement_id=?",
        (engagement_id,),
    ).fetchone()

    if not config_row:
        logger.warning("No monitoring config found for engagement %d.", engagement_id)
        con.close()
        return 0

    keywords = json.loads(config_row["keywords_json"])
    since_dt = since or datetime.fromisoformat(config_row["started_at"])

    inserted = 0

    with httpx.Client(timeout=30) as client:
        for keyword in keywords:
            try:
                resp = client.get(
                    f"{LEAKLOOKER_BASE}/search",
                    headers={"X-API-Key": api_key},
                    params={"query": keyword, "since": since_dt.isoformat()},
                )
                resp.raise_for_status()
                findings = resp.json().get("results", [])

                for finding in findings:
                    paste_url   = finding.get("url", "")
                    paste_hash  = _hash_url(paste_url)
                    platform    = finding.get("source", "unknown")
                    cred_count  = finding.get("credential_count", 0)
                    plain_count = finding.get("plaintext_count", 0)
                    severity    = _classify_severity(cred_count, plain_count)
                    discovered  = finding.get("discovered_at", datetime.now(tz=timezone.utc).isoformat())
                    excerpt     = finding.get("excerpt", "")

                    # Check for duplicate
                    exists = con.execute(
                        "SELECT 1 FROM monitoring_findings WHERE paste_id_hash=? AND engagement_id=?",
                        (paste_hash, engagement_id),
                    ).fetchone()

                    if exists:
                        continue

                    con.execute(
                        """
                        INSERT INTO monitoring_findings
                            (engagement_id, paste_id_hash, source_platform, discovered_at,
                             keyword_matched, credential_count, plaintext_count,
                             excerpt_available, excerpt_enc, severity)
                        VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
                        """,
                        (
                            engagement_id, paste_hash, platform, discovered,
                            keyword, cred_count, plain_count,
                            1 if excerpt else 0,
                            excerpt,   # TODO: encrypt with engagement AES key (Chunk 0)
                            severity,
                        ),
                    )
                    inserted += 1

                logger.info(
                    "LeakLooker: keyword=%r — %d new findings.", keyword, inserted
                )

            except httpx.HTTPStatusError as exc:
                logger.error("LeakLooker API error for keyword %r: %s", keyword, exc)
            except httpx.RequestError as exc:
                logger.error("LeakLooker network error: %s", exc)

    con.commit()
    con.close()
    return inserted
```

> **Key design decisions:**
> - **URL hashing:** Paste URLs are SHA-256 hashed before storage. Raw paste URLs must never
>   appear in the DB or in generated reports. If the operator needs to manually review a paste,
>   they retrieve the URL via a separate operator-only CLI command (`forge monitor get-url --hash <hash>`)
>   that requires interactive confirmation and logs the access.
> - **Excerpt encryption:** Raw paste excerpts, if retained, should be encrypted at rest using
>   the engagement AES key (defined in Chunk 0). The `excerpt_enc` field stores the ciphertext;
>   plaintext is never written to the DB. The current implementation stores plaintext as a
>   temporary measure; encrypt before the Phase 6 milestone.
> - **Rate limiting:** LeakLooker enforces per-minute request limits on free-tier API keys.
>   Implement exponential backoff (as defined for other API calls in Phase 2) on HTTP 429 responses.

CREATE TABLE IF NOT EXISTS monitoring_config (

    engagement_id   INTEGER NOT NULL REFERENCES engagements(id) UNIQUE,

CREATE TABLE IF NOT EXISTS monitoring_findings (

| Risk | Mitigation |
|------|------------|
| LeakLooker API key stored in DB or config file | Always read from environment variable (`$LEAKLOOKER_API_KEY`); never persist in `engagement_config` or any DB table |
| Raw paste URLs in DB expose operator awareness | All URLs are SHA-256 hashed at ingest; plaintext URL is never persisted. Retrieval requires explicit `forge monitor get-url` with audit logging |
| Paste excerpts leak credential content into DB | Excerpts encrypted with engagement AES key (Chunk 0) at ingest time. Plaintext excerpts are never written to disk |
| Monitoring poll timing creates a traceable pattern | `forge monitor poll` should only be called from operator infrastructure, not from a compromised host. It is not part of the C2 beacon cycle |
| `--include-monitoring` flag in generated reports reveals monitoring capability | Report metadata (file path, report content) must be sanitised before delivery. Default filename `engagement_<id>_report.*` should be renamed per §11.12 |
| New findings inflate perceived engagement scope | The monitoring section is clearly labelled with its time window. The Executive Summary must not conflate monitoring findings with active engagement findings |
