Key Findings

  1. BloodHound's strongest transferable advantage is not a scanner; it is a collector-fed relationship graph plus quality/review workflow. FORGE already has graph, report, audit, validation, and ownership primitives, so the concrete gap is import normalization and data-quality scoring.
  2. AzureHound and SharpHound show that FORGE should make "collector output import" a first-class workflow. Offline JSON/zip import fits FORGE's deterministic, non-destructive model better than running collectors directly.
  3. Nemesis validates FORGE's artifact-analysis direction, but FORGE needs a clearer artifact workbench: queue state, parser lineage, extracted entities, failure reasons, and safe reprocess plans.
  4. Mythic, Merlin, and CrucibleC2 are relevant for collaboration, plugin boundaries, and eventing patterns only. Their C2/agent capabilities are intentionally excluded from this roadmap.
  5. SharpSCCM, SharpCloud, StayKit, and Malleable C2 are best treated as defensive taxonomy and linting references. They should feed checklist mappings, artifact classifiers, and remediation content, not execution modules.

Proposed Next Step

Create a focused spec for the BloodHound-family offline import connector: supported SharpHound zip and AzureHound JSON fixture formats, graph node/edge normalization, provenance rows, data-quality metrics, dashboard/report surfacing, and fail-closed tests. This is the highest-value next action because it strengthens FORGE's graph, validation, review, artifact-analysis, and fallback gates without adding unsafe execution behavior.

Guardrails

  • Do not scrape behind logins or bypass access controls.
  • Do not copy proprietary UI, text, branding, or private workflows.
  • Do not clone competitor features without adapting them to FORGE's deterministic, authorized engagement model.
  • Do not use undated claims; every external product claim in this plan is dated 2026-08-31.
  • Do not hide uncertainty; the ODI URL remains unresolved until the exact repository is confirmed.
  • Do not turn competitor research into busywork; prioritize the smaller set of upgrades that improve the locked release gates.
