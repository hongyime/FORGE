Competitive research verdicts

Four tools, two architectures, one goal-lock-grounded verdict per tool. The verdict is driven by whether a pattern survives assert_in_scope, validation-before-reporting, and deterministic risk scoring — not by whether the tool is clever.

● ADOPT

Strix

usestrix/strix · Apache-2.0 · OpenAI Agents SDK + Docker sandbox

Adopt: tool-wrapper patterns (bounded output, argument coercion, error-as-result). Add strix_findings_import connector in the import-validation family.

Reject: autonomous exploit execution. FORGE validates; Strix exploits. The two postures are mutually exclusive under validation-before-reporting.

● ADOPT

Cairn

oritera/Cairn · blackboard architecture · stigmergy coordination

Adopt: the Fact / Intent / Hint evidence model. Formalize FORGE's recursion decisions in a recursion_intents table + forge recursion command namespace.

Reject: Cairn's "any goal, any domain" open-ended search. FORGE's goal lock requires deterministic, pre-defined goals — not operator-provided free-form targets.

○ CATALOG-ONLY

Muraena

muraenateam/muraena · Go reverse-proxy phishing framework

Study: the no-regex strings.NewReplacer sorted-pair transformer pattern (core/proxy/replacer.go) as a code-level reference.

Reject: reverse-proxy transport accepts arbitrary victim traffic — a direct violation of assert_in_scope. Live MFA cookie capture violates the "no raw credentials persisted" invariant. Catalog as adversary-emulation reference only.

○ CATALOG-ONLY

Necrobrowser

muraenateam/necrobrowser · Node.js Puppeteer cluster

Study: the {type, name, params} task JSON contract and Redis task-loader pattern (minus the eval dispatch) — informs Collection Profile Manifests (backlog #7).

Reject: every post-login task (SharepointExtrude, OneDriveExtrude, OutlookExtrude, AddAuthenticatorApp) violates the non-destructive validation gate. Serves as the explicit anti-example for the Authenticated Scraping spec (Open Question #1).

3-wave integration roadmap

Ordered by prerequisite depth. Each wave is bounded; Wave 1 ships without new primitives, Wave 2 adds the first new tables/commands, Wave 3 opens new interface surfaces.

WAVE 1

Ship in next release

Hardening passes · no new primitives · low effort
  1. Apply Strix-style tool wrappers (bounded output, argument coercion, error-as-result) universally across forge/connectors/* and forge/phase4/* — pattern is already partial
  2. Add strix_findings_import connector mirroring the existing Burp DAST XML import path (forge connectors import-validation family)
  3. Add Muraena + Necrobrowser as catalog-only entries in forge connectors policy-summary — documents the stance, costs nothing operationally
WAVE 2

Next backlog slot

New primitives · medium effort · DB + CLI surface
  1. Formalize Fact / Intent / Hint — new recursion_intents table + forge recursion command namespace. Backfills the audit story for recursion decisions.
  2. Collection Profile Manifests (backlog Do Next #7) using Necrobrowser-shape JSON contract (operator-visible, operator-editable, scope-gated — no eval dispatch)
  3. API-spec seed type for passive route enumeration (OpenAPI / Postman / Swagger as scoped seed), parser + scope-manifest extension
WAVE 3

Longer bet

Interface surfaces · medium-high effort · spec work
  1. forge mcp serve — expose FORGE evidence (hosts, services, findings, graph) via Model Context Protocol so coding agents can read engagement state through the same channel they use for other MCP servers
  2. forge.skill.v1 manifest + skill registry for coding-agent delegation (aligns with existing operator-guide command)
  3. Write the Authenticated Scraping policy spec (Open Question #1) using Necrobrowser as the explicit anti-example — enumerate each capability and declare each out-of-scope
