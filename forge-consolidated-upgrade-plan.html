Executive Summary

This document merges three independent research streams — SpecterOps ecosystem analysis (Plan 1), Offensive Security competitive review (Plan 2), and the ODIN open-source OSINT framework — into a single actionable roadmap for FORGE. All results are cross-referenced against Codex verification on commit f3041c1. Sixteen upgrades are tiered as Do Now Do Next Explore.

FORGE's five confirmed differentiators should be defended and never regressed: multi-seed ASM intake, deterministic pipeline, hash-chain audit logging, PyArmor obfuscation (19 files, 2.06 MiB verified), and Rust AES-GCM/BLAKE3 crypto (9 cargo tests passing).

Critical: Five Rust functions (parse_kirbi, enumerate_kerberoast_candidates, extract_from_lsass, extract_from_sam, pth::execute) return placeholder data. Do NOT claim "Rust core complete" beyond AES-GCM/BLAKE3. See Codex Rust Status section.

⚡ Do Now — 6 Upgrades

BloodHound-Family Offline Import Connector
Plan 1 Medium Effort High Priority Inspired by: SharpHound / AzureHound JSON bundles
Accept SharpHound/AzureHound JSON zip bundles as an offline import path; normalize into FORGE's collector-fed graph + quality workflow. Closes the single largest data-ingestion gap vs. the BloodHound ecosystem without requiring live agent connectivity.
Graph Data-Quality Report
Plan 1 Low Effort Medium Priority Inspired by: BloodHound data quality scoring
Auto-generate completeness/consistency report after each collection run (node coverage, missing edges, stale timestamps). Extends the existing FORGE report infrastructure; low effort because the report scaffolding already exists.
Artifact Enrichment Status Tab
Plan 1 Medium Effort High Priority Inspired by: Nemesis workbench UX
Surface the existing artifact queue as a UI tab showing enrichment state per artifact (pending / processing / complete / failed). Brings FORGE operator visibility closer to Nemesis-style UX without a full Nemesis dependency.
Cloud Credential Collector
Plan 2 Low Effort High Priority Inspired by: SharpCloud patterns
Formalizes the partial cloud credential capability into a deterministic, auditable module: harvest AWS/Azure/GCP credentials from environment variables, config files, and metadata endpoints. Each harvest step is hash-chain logged and gated by ROE flags.
Graph UI — Client-Side (Sigma.js / D3 bundled locally)
Plan 2 Low Effort High Priority Inspired by: BloodHound graph UI, ODIN Neo4j view
Add a real-time graph visualization layer using Sigma.js or D3 bundled locally (no CDN). Closes the "no graph UI" gap identified in both Plan 2 and ODIN analysis. Sigma.js library should be vendored into the FORGE assets directory.
Session Enumeration Module
Plan 2 Low Effort Medium Priority Inspired by: C2 eventing patterns (boundary only)
Enumerate active sessions on target hosts and feed results into the deterministic pipeline. Addresses the C2-pattern collection gap without introducing C2 listener infrastructure. Output normalized to FORGE graph schema and hash-chain logged.

🔶 Do Next — 5 Upgrades

Collection Profile Manifests
Plan 1 Medium Effort Medium Priority
Declarative YAML/JSON manifests defining which collectors run, in which order, with pre/post conditions and expected output schemas. Improves reproducibility of engagements; makes the deterministic pipeline observable and shareable across operators.
Unified Engagement Activity Timeline
Plan 1 Medium Effort Medium Priority Inspired by: BloodHound analysis timeline, ODIN 4-phase reporting
Cross-phase chronological timeline pulling events from the hash-chain audit log. Gives operators a single pane for reviewing engagement history; leverages existing audit infrastructure so the incremental work is visualization only.
AD / LDAP Collection Module
Plan 2 Medium Effort High Priority Inspired by: BloodHound / SharpHound
Python or Rust LDAP module for pulling user/group/computer/trust data from Active Directory. Closes the single largest "Missing" gap vs. BloodHound/SharpHound and unblocks hybrid path derivation. Rust scaffolding exists at kerberos.rs:57 (currently returns empty Vec — needs LDAP queries wired in).
AzureHound Data Ingestion
Plan 2 Medium Effort High Priority Inspired by: AzureHound / BloodHound CE
Accept and normalize AzureHound JSON output alongside the BloodHound-family import connector. Prerequisite for hybrid path derivation. Delivers Azure tenant visibility (service principals, managed identities, role assignments) into the FORGE graph.
Hybrid Path Derivation
Plan 2 Medium Effort High Priority Inspired by: BloodHound v5.13 primary differentiator
Combine on-prem AD graph with Azure tenant data to surface cross-boundary attack paths (e.g., on-prem user → Azure SP → privileged role). Mirrors BloodHound v5.13's key moat. Depends on: AD/LDAP module + AzureHound ingestion both shipping first.

🔭 Explore — 5 Upgrades

Neo4j / OpenGraph Export Bridge
Plan 1 High Effort Medium Priority ODIN has this natively
Native Neo4j export (Cypher / APOC) so FORGE graphs can be analyzed in external tools. High effort due to schema design, round-trip fidelity, and version compatibility requirements. ODIN ships this out of the box; FORGE currently missing.
Nemesis-Compatible Artifact Handoff
Plan 1 High Effort Medium Priority
Implement a Nemesis-compatible artifact submission API so FORGE artifacts can be forwarded for deeper post-processing. Requires studying Nemesis protobuf schema and maintaining compatibility across Nemesis versions; considerable integration cost.
Agent Ecosystem — Collaboration Patterns Only
Plan 2 High Effort Low Priority
Adopt eventing and plugin-boundary patterns from Merlin/Mythic/Crucible for inter-tool orchestration. Collaboration patterns ONLY — no C2 listener, no agent beacon, no in-memory execution. See Do Not Copy section for hard constraints.
OpenGraph Plugin Interface
Plan 2 High Effort Medium Priority
Define a stable plugin interface for external graph providers (BloodHound, ODIN, custom Neo4j) so FORGE can act as an orchestration layer without owning every graph implementation. Enables long-term ecosystem flexibility; depends on Neo4j bridge being stable first.
Attack Path Management Framework
Plan 2 High Effort Low Priority
Structured framework for tracking, prioritizing, and reporting attack paths identified during an engagement — linking paths to MITRE techniques, risk scores, and remediation recommendations. Long-term product differentiator; gate on graph visualization + hybrid paths being stable first.

❓ Open Questions

1. Authenticated Scraping Policy Change

User wants authenticated scraping allowed. Requires: (a) ROE manifest update with explicit scope field, (b) per-request authorization checks, (c) audit log entries with credential-type tag for each authenticated request. Action: defer to a separate authenticated-scraping spec — do not implement without signed-off spec.

2. Rust Native Behavior Expansion

Expand Rust beyond AES-GCM/BLAKE3 crypto. Each "Still Limited" function requires: (a) explicit safe-flag gating in the calling pipeline, (b) authorization check at invocation, (c) audit log entry. Immediate unblock path: asn1-rs for parse_kirbi; Windows API access plan for lsass/SAM extraction. Action: create per-function expansion tickets, each linked to the AD/LDAP module milestone.

3. C2 Infrastructure Boundary Definition

Explore-tier agent ecosystem work must be limited to plugin boundaries and eventing patterns. No C2 listener, no agent beacon, no in-memory staging. Action: write and publish a plugin-boundary spec before any Explore-tier C2 pattern work begins. Spec must define what events may cross the boundary.

🚫 Do Not Copy

⛔ Out-of-Scope Patterns — Hard Constraints

  • Persistence execution menus (StayKit) — use defensive indicators instead; persistence-as-a-feature is out of scope for FORGE's goal
  • C2 listener / agent features (Merlin / Mythic / Crucible) — collaboration patterns and plugin-boundary eventing ONLY; no beacon, no agent lifecycle, no in-memory staging or shellcode execution
  • AV bypass / in-memory execution — not needed for FORGE's pipeline goal; adds detection surface with no benefit; PyArmor obfuscation already handles necessary protection
  • ODIN's non-deterministic gates — FORGE's deterministic pipeline is a verified strength; do not regress it by adopting ODIN's looser collection sequencing
  • ODIN's SQLite-only storage and no-fallback reporting — FORGE has richer storage and fallback patterns; do not replace them with ODIN's simpler but less resilient approach
